# 深度研究功能集成设计（SuperSonic × miro-flow-solution）

> 目标：在 SuperSonic 问数成功并完成描述性解读后，引导用户触发 Python 深度研究 Agent（miro-flow-solution），产出归因报告并回挂到当前 `queryId`。
> 指标与开场口径：[`01-通用问答.md`](./01-通用问答.md)；题纲 B5 / C9 / D 节。
> 状态：设计定稿，待编写实现计划（writing-plans 阶段）。
> 协议契约原则：**协议先就绪、实现可渐进**——Demo 阶段每项只做最小实现，但字段和抽象接口先留好，未来演进无损。

## 1. 项目背景

### 1.1 B5 文档描述的产品形态

- 用户问数成功并完成描述性解读后，结果区展示「想要对结果做深度研究吗？」
- 用户点击 = 启动深度研究，前端只传当前 `queryId`
- Java 按该 `queryId` 取出原问题、`textResult`/`textSummary`、维度/指标，截断后拼成 `task + context`
- Java 写表后同步 `POST` Python `/v1/research/jobs`，等接单 `200`（SQLite `INSERT PENDING` 成功，落库即入队）再把 `jobId` 回给前端；**不**等 pipeline，也**不**在问数 execute 线程里跑研究
- 前端订阅 Java 取终态；成功写入短报告字段；失败静默保留 `textSummary`

### 1.2 双方代码现状落差

| 维度 | 现状 | 差距 |
|------|------|------|
| Python 任务执行通道 | 仅 WebSocket `/ws`（session 1:1 task，纯内存） | 需新增 REST `/v1/research/jobs` 异步 job 契约 |
| Python 任务状态持久化 | 无（仅 TaskTracer JSON 日志，无 load 入口） | 需新增 SQLite job store + 启动恢复 |
| Java 异步 job 框架 | 无（仅 textSummary 伪流式轮询） | 需新建 `s2_chat_research_job` 表 + 网关层 |
| 前端轮询/推送 | ChatItem 500ms 轮询 `getExecuteSummary` | 新增 SSE 推送通道 |
| traceId | Java MDC + LogInterceptor，链路完整 | 需 HTTP header 透传到 Python |

### 1.3 实现目标

**端到端跑通 Demo**：Java 网关 + Python REST + 前端 SSE，三个本地进程能从点击按钮看到深度报告产出。

## 3. 整体架构

### 3.1 数据流总览

```
[用户] 在 ChatItem 结果区点击"深度研究"
   │
   ▼  POST /api/chat/research/query/{queryId}        (前端 → Java)
[Java 网关]
   - UserHolder.findUser() 拿当前用户
   - permissionChecker.check(user)  ← 权限+配额+并发
   - 从 ChatQueryDO 取 question + textResult + textSummary + 维度/指标
   - 截断拼成 task + context
   - 生成 jobId = UUID，拿 traceId
   - 写 s2_chat_research_job(PENDING)
   - 同步 POST Python（Bearer SERVICE_TOKEN + X-Trace-Id）
   │
   │                                              ────►  [Python miro-flow]
   │                                                     FastAPI dependency 验 SERVICE_TOKEN（相等校验）
   │                                                     IntentClassifier 本地 0.5B 三分类
   │                                                     TypeToConfig 映射
   │                                                     写 SQLite(PENDING) 即入队
   │                                                     立即返回 200 + job_id
   │                                                     独立 worker 扫表抢 PENDING
   │
   ▼  拿到 200 后返回 {jobId, status:PENDING}；失败则标 FAILED，创建接口失败
   ▼  EventSource 订阅 /api/chat/research/{jobId}/stream
[前端]                                          [Python pipeline 运行]
   - 先 GET 当前状态                                - execute_task_pipeline
   - 终态则关闭                                     - 长度控制（句子边界截断）
   - 订阅 SSE                                       - 写 outputs/{tenant}/research_jobs/{job_id}.json
   - onerror 3 秒重连                               - 更新 SQLite(COMPLETED)
                                                       │
[Java @Scheduled fixedDelay=2000]                       │
   - 扫 s2_chat_research_job WHERE status = PENDING
   - 对每条记录 GET /v1/research/jobs/{jobId}
   - Python 报 COMPLETED/FAILED → 更新本地表 + 推 SSE
   - Python 报 PENDING/RUNNING → Java 保持 PENDING，不推 SSE
   - 超时（15min，时钟 created_at）→ 标 FAILED
```

### 3.2 两个独立方向（关键澄清）

| 方向 | 机制 | 频率 |
|------|------|------|
| Python 状态 → Java 表 | Java `@Scheduled` 主动拉 Python | 每 2 秒 |
| Java 表 → 前端 UI | Java SSE 推送 + GET fallback（首次/重连） | 事件驱动 |

**关键设计**：Java→Python 流量与前端用户数解耦。100 个用户同时轮询，Java 仍然每 2 秒一次固定频率向 Python 发请求。

### 3.3 Python 内部处理流（意图识别 → 分发 → 执行）

Python 服务接到 POST 后**内部**的处理链路（详细 ASCII 图见 §7.0）：

```
POST /v1/research/jobs 接到请求
   │
   ▼  同步路径（落库即入队后返回 200）
[FastAPI middleware] → trace_id 注入 contextvar
   │
   ▼
[deps.verify_service_token] → 401 失败
   │
   ▼
[routes.create_job]
   │
   ├─ IntentClassifier.classify(query)
   │    └─ FastAPI 进程内 Qwen2.5-0.5B → JSON {label}
   │       映射为 research_type；失败 fallback default
   │       吃 Java 已截断的整段 query，Python 不再切
   │
   ├─ JobStore.create(... status=PENDING)   ← SQLite INSERT = 入队
   │
   └─ return 200 {job_id, status:PENDING}

            ─── 独立 worker（扫表 + Semaphore(4)）───

claim_one_pending()  →  CAS PENDING→RUNNING → run_pipeline_async(...)
   │
   ▼
[幂等守卫] 已终态则直接 return
   │
   ▼
[QueryRewriter.rewrite]
   └─ default：pipeline 同一套 chat API 改写（20s）；失败用原文
   └─ financial_analyst/academic：原样返回
   │
   ▼
[ResearchDirective.compose_task]
   ├─ 加载核心模板：research_prompts/{type}.md
   └─ 拼成 <research_directive>...</research_directive>
   │
   ▼
[asyncio.wait_for(execute_task_pipeline, timeout=14min)]
   │
   ├─ Main Agent 多轮工具调用（MCP + sub-agents + max_turns）
   ├─ 超时 → PipelineTimeoutError
   └─ 产出：final_answer + boxed_answer
   │     ↑ Main–Sub 编排精读见 [`03` §1.2–§1.3](./03-Main-Sub-Agent编排.md#12-上游衔接用户-query-如何进到-mainsub)
   │
   ▼
[enforce_length_budget] 句子边界截断
   │
   ▼
[ReportStore.save] → outputs/{tenant}/research_jobs/{job_id}.json
   │
   ▼
[JobStore.update(status=COMPLETED, summary, uri)]   ← 终态不可变守卫
```

**Python 内部三层职责**（§7.4/§7.5/§7.6 详述）：

| 层 | 组件 | 职责 |
|----|------|------|
| 分类层 | IntentClassifier | 本地 0.5B 判断 `research_type`（无 `data_domain`） |
| 改写层 | QueryRewriter | 仅 `default` 调 pipeline 同一套 chat API；另外两类原样 |
| **Query enhance 装配层** | ResearchDirective | 按 type 把范式 md **prepend 进 task** |

一句话：**Intent 之后的路由，本质是 query enhance，不是切换 Main 的 `prompt_class`。** 两类特定增强——`financial_analyst`、`academic`——外加兜底 `default`（先改写问句再拼 `default.md`）。领域知识不进分类器，交给 14 分钟大模型。

**与 Java 侧的边界**：Java 只看到 HTTP；所有路由、prompt 拼接、pipeline 执行、状态迁移都在 Python 内部完成。Java 通过 @Scheduler 拉 SQLite 状态，是"观察者"不是"参与者"。

## 4. 跨服务契约

### 4.1 REST 契约（Java ↔ Python · 内部）

**POST `/v1/research/jobs`**（Python 新增）

Headers:
```
Authorization: Bearer <RESEARCH_SERVICE_TOKEN>
X-Trace-Id: supersonic_<UUID>
Content-Type: application/json
```

Request body:
```json
{
  "job_id": "uuid-由-Java-生成",
  "trace_id": "supersonic_xxx",
  "tenant_id": "default",
  "query": "Java 拼好的整段（原问题 + 表格 + 解读）",
  "retrieval_mode": "hybrid",
  "length_budget": 4000
}
```

Response 200:
```json
{ "job_id": "...", "status": "PENDING" }
```

`200` 表示创建成功（SQLite 已有这一行）。INSERT 因磁盘/锁失败回 `503`，库里没有行。同一 `job_id` 再 POST 撞主键视为幂等成功，仍 `200`（回包丢失时的重试，不能当失败）。

**GET `/v1/research/jobs/{job_id}`**（Python 新增）

Headers 同 POST：`Authorization: Bearer <RESEARCH_SERVICE_TOKEN>`，可选 `X-Trace-Id`。

Response 200:
```json
{
  "job_id": "...",
  "tenant_id": "default",
  "trace_id": "...",
  "research_type": "financial_analyst",
  "status": "PENDING | RUNNING | COMPLETED | FAILED",
  "report_uri": "fs://outputs/default/research_jobs/{job_id}.json",
  "error_msg": "...",
  "created_at": "...",
  "updated_at": "...",
  "started_at": "...",
  "completed_at": "..."
}
```

Query 参数 `?include_full=true`：按需读取完整报告 JSON 文件并返回 `report_full` 字段（Java 在 COMPLETED 时拉一次）。

### 4.2 REST 契约（前端 ↔ Java · 外部）

| 方法 | 路径 | 响应 |
|------|------|------|
| POST | `/api/chat/research/query/{queryId}` | `200 {jobId, status:PENDING}` / `400`（无 textSummary）/ `403`（无权限）/ `429`（配额）/ `409`（并发） |
| GET | `/api/chat/research/{jobId}` | `200 {jobId, queryId, status, reportFull?, errorMsg?}` |
| GET | `/api/chat/research/{jobId}/stream` | `SseEmitter`（`text/event-stream`，只推 COMPLETED / FAILED） |

### 4.3 状态机

两套状态，不要混：

**Python**（执行态，SQLite）

```
PENDING ──► RUNNING ──► COMPLETED
   │           │
   └──► FAILED ◄┘
        （pipeline 异常 / 14min 硬超时 / 启动恢复）
```

**Java**（用户可见态，`s2_chat_research_job`）

```
PENDING ──► COMPLETED
   │
   └──► FAILED
        （创建失败 / Python 明确失败 / 孤儿 / 15min 兜底）
```

Java **没有 `RUNNING`**。创建已同步等到 Python 落库 `200`，未完成就是 `PENDING`。Scheduler 拉到 Python `PENDING` / `RUNNING` 时保持 `PENDING`，不推 SSE；只有 `COMPLETED` / `FAILED` 才写表并推前端。

**状态迁移规则**：

| 迁移 | 触发时机 | 实现位置 |
|------|----------|----------|
| Python → PENDING | POST `/v1/research/jobs` 收到请求 | `routes.py` create_job |
| Python → RUNNING | worker `claim_one_pending` CAS 抢到行 | `worker.py` → `pipeline_adapter.py` |
| Python → COMPLETED | `execute_task_pipeline` 正常返回 | `pipeline_adapter.py` try 块末尾 |
| Python → FAILED | pipeline 异常 / 14min 硬超时 / worker 收尸 | `pipeline_adapter.py` / `recover_stale_jobs` |
| Java → PENDING | 创建接口写表（等接单 200 后返回） | `ResearchJobServiceImpl` |
| Java → COMPLETED / FAILED | Scheduler 拉到 Python 终态，或创建失败 / 15min 兜底 | `ResearchSyncScheduler` / createResearch |

**终态不可变约束**（消除 Java/Python 状态分叉）：

- 一旦 job 进入 `COMPLETED` 或 `FAILED`，**任何后续状态写入都被拒绝**
- Python `job_store.update()` 校验当前状态：若已终态，跳过更新并记录 warning
- Java `mergeStatus()` 同样校验：若本地表已终态，拒绝 Python 回包覆盖
- 这是评审 #6 的根本修复——防止「Java 超时标 FAILED → Python 后完成标 COMPLETED」造成永久分叉

### 4.4 关键设计决策（8 条）

1. **jobId 由 Java 生成**（UUID）——Java 控制命名空间，Python 不自创 task_id
2. **traceId 从 Java MDC 透传到 Python**——HTTP header `X-Trace-Id`，便于事后排查
3. **路由由 Python 全权决策**——IntentClassifier 判断类型 → ResearchDirective 选 prompt，Java 只传 `task + context`，不感知业务
4. **前端永远不直连 Python**——所有调用过 Java 网关
5. **Python 是超时唯一权威**（评审 #6 修复）——`asyncio.wait_for` 硬超时 14 分钟，保证 Python 永远在 14min 内进入终态；Java 15 分钟仅作兜底（worker 崩溃、网络分区等极端情况）
6. **终态不可变**（评审 #6 修复）——COMPLETED/FAILED 一旦写入，任何反向覆盖都被拒绝；消除双写一致性问题
7. **Java 超时时钟用 `created_at`**——创建已等过接单，排队只有秒级；不必在 Java 表再拆 `RUNNING` / `started_at` 做超时。Python 硬超时仍用自己的 `started_at`。
8. **出站用静态 SERVICE_TOKEN**——用户权限在 Java 做完；Compose 默认网络按服务名互访，同网络容器都能打到 Python，相等校验挡住旁路调用。不转传 SuperSonic 用户 JWT，也不现签。

创建接口：**写表后同步 POST Python**，等接单 `200`（SQLite 落库即入队）再返回。不用 `@Async` / `CompletableFuture`：接单是秒级，研究是分钟级；异步出站只让转圈早几秒，接单失败却变成空 `PENDING`。失败当场标 `FAILED`，创建接口失败。Java 表状态只有 `PENDING / COMPLETED / FAILED`，不抄 Python 的 `RUNNING`。

### 5.4 `useResearchJobStream` hook

```typescript
// hooks/useResearchJobStream.ts
import { useEffect, useState } from 'react';
import { getResearchStatus } from '../service';

export type JobStatus = 'PENDING' | 'COMPLETED' | 'FAILED';

export interface ResearchState {
    status: JobStatus | null;
    report: string | null;
    errorMsg: string | null;
}

export function useResearchJobStream(jobId: string | null): ResearchState {
    const [state, setState] = useState<ResearchState>({
        status: null, report: null, errorMsg: null,
    });

    useEffect(() => {
        if (!jobId) return;

        let eventSource: EventSource | null = null;
        let reconnectTimer: ReturnType<typeof setTimeout> | null = null;
        let closed = false;

        const connect = async () => {
            if (closed) return;

            try {
                // 1. 先 GET 当前状态（避免 SSE 不推当前状态的问题）
                const current = await getResearchStatus(jobId);
                setState({
                    status: current.status,
                    report: current.reportFull ?? null,
                    errorMsg: current.errorMsg,
                });

                // 已终态：不订阅
                if (current.status === 'COMPLETED' || current.status === 'FAILED') {
                    return;
                }

                // 2. 订阅 SSE
                eventSource = new EventSource(`/api/chat/research/${jobId}/stream`);

                eventSource.onmessage = (e) => {
                    const data = JSON.parse(e.data);
                    setState({
                        status: data.status,
                        report: data.reportFull ?? null,
                        errorMsg: data.errorMsg,
                    });
                    if (data.status === 'COMPLETED' || data.status === 'FAILED') {
                        eventSource?.close();
                    }
                };

                eventSource.onerror = () => {
                    eventSource?.close();
                    if (!closed) {
                        reconnectTimer = setTimeout(connect, 3000);   // 3 秒重连
                    }
                };
            } catch (err) {
                if (!closed) {
                    reconnectTimer = setTimeout(connect, 3000);
                }
            }
        };

        connect();

        return () => {
            closed = true;
            eventSource?.close();
            if (reconnectTimer) clearTimeout(reconnectTimer);
        };
    }, [jobId]);

    return state;
}
```

```tsx
        researchFeature.runningJobId
    );
    const { status, report, errorMsg } = useResearchJobStream(jobId);

    const handleStart = async () => {
        try {
            const res = await createResearchJob(queryId);
            setJobId(res.jobId);
        } catch (err) {
            // 静默失败（权限/配额/并发已在 service 层抛出）
            console.warn('[research] start failed', err);
        }
    };

    // ✗ FAILED：不渲染（静默保留 textSummary）
    if (status === 'FAILED') {
        return null;
    }

    // 进行中
    if (status === 'PENDING') {
        return <ResearchProgress status={status} />;
    }

    // 完成
    if (status === 'COMPLETED' && report) {
        return (
            <ResearchReport content={report} />
        );
    }

    // 默认：启动按钮
    return (
        <ResearchTrigger
            remainingToday={researchFeature.remainingToday}
            runningJobId={researchFeature.runningJobId}
            onStart={handleStart}
        />
    );
}
```

### 5.7 关键交互细节

**场景 1：页面刷新后继续订阅**
- `queryResult.researchFeature.runningJobId` 不为 null（Java 表里 `PENDING` 的 job）
- ResearchItem 初始 jobId 即 `runningJobId`，自动续订 SSE
- 用户体验：刷新后看到"正在深度研究中..."

**场景 2：用户离开页面后回来**
- EventSource 在组件 mount 时重新建立
- `useResearchJobStream` 先 GET 拿当前状态，可能直接是 COMPLETED → 跳过 SSE 订阅

**场景 3：深度研究失败**
- SSE 收到 `{status: 'FAILED', errorMsg: '...'}`
- ResearchItem 返回 `null`，不渲染任何东西
- 用户只看到原表格 + textSummary
- 失败原因在浏览器 console + Java logback 日志里

**场景 4：Python 服务挂了**
- **创建时就挂**：同步 POST 超时/失败 → 表标 `FAILED`，创建接口 503，前端不进入 loading
- **已经接单、pipeline 在跑时挂**：SSE 连的是 Java，不受 Python 进程影响；Scheduler GET 失败当抖动跳过；15 分钟兜底标 FAILED → 推送 → UI 静默隐藏

### 5.8 与现有轮询模式的关系

**两条独立的状态获取路径**：

| 数据 | 获取方式 | 管理者 |
|------|----------|--------|
| `textSummary`（描述性解读） | 500ms 轮询 `getExecuteSummary` | `ChatItem/index.tsx` 现有逻辑 |
| 深度研究状态 | SSE 推送 | `ResearchItem` + `useResearchJobStream` |

**互不干扰**：textSummary 轮询失败不影响深度研究 SSE；深度研究挂了不影响 textSummary 展示。

### 5.9 前端不做的事

- 取消按钮（Demo 范围）
- 进度条/百分比（PENDING 一态转圈即可）
- 历史报告列表
- 报告导出按钮
- 用户反馈/评分
- toast 提示（静默失败原则）

```java
@Component
public class ResearchOwnershipChecker {

    @Autowired private ResearchJobMapper jobMapper;
    @Autowired private ChatQueryService chatQueryService;

    public void checkJobOwnership(User user, String jobId) {
        ResearchJobDO job = jobMapper.selectById(jobId);
        // 不存在或非本人 → 统一抛 NOT_FOUND（不泄露 jobId 存在性，防枚举）
        if (job == null) {
            throw new ResearchNotFoundException("job not found");
        }
        boolean isAdmin = Integer.valueOf(1).equals(user.getIsAdmin());
        if (!isAdmin && !job.getCreatedBy().equals(user.getId())) {
            throw new ResearchNotFoundException("job not found");
        }
    }

    public void checkQueryOwnership(User user, Long queryId) {
        ChatQueryDO query = chatQueryService.getChatQuery(queryId);
        if (query == null) {
            throw new ResearchBadRequestException("query not found");
        }
        // query 归属校验：通过 userName 或 agentId 判断
        // Demo 简化：admin 放行；非 admin 必须是 query 创建者
        boolean isAdmin = Integer.valueOf(1).equals(user.getIsAdmin());
        if (!isAdmin && !Objects.equals(query.getUserName(), user.getName())) {
            throw new ResearchPermissionException("query does not belong to user");
        }
    }
}
```

1. **不存在和非归属统一返回 404**：不泄露 jobId 存在性，防枚举攻击

#### 6.3.2 `ResearchJobServiceImpl` · 业务流程

```java
@Service
public class ResearchJobServiceImpl implements ResearchJobService {

    @Autowired private ChatQueryService chatQueryService;
    @Autowired private ResearchPermissionChecker permissionChecker;
    @Autowired private PythonResearchClient pythonClient;
    @Autowired private ResearchJobMapper jobMapper;
    @Autowired private ResearchSseRegistry sseRegistry;

    @Override
    public CreateJobResponse createResearch(User user, Long queryId) {
        // 1. 取 ChatQueryDO（复用现有 API）
        ChatQueryDO query = chatQueryService.getChatQuery(queryId);
        if (query == null || StringUtils.isEmpty(query.getTextSummary())) {
            throw new ResearchBadRequestException(
                "查询结果不存在或无描述性解读");
        }

        // 2. 权限 + 配额 + 并发校验
        permissionChecker.check(user);

        // 3. 组装 task + context（截断到 ≤ 4000 字）
        String task = query.getQuestion();
        String context = buildContext(query);

        // 4. 生成 jobId + 拿 traceId
        String jobId = UUID.randomUUID().toString();
        String traceId = TraceIdUtil.getTraceId();

        // 5. 写 Java 表（PENDING）
        ResearchJobDO job = new ResearchJobDO();
        job.setJobId(jobId);
        job.setQueryId(queryId);
        job.setTenantId("default");
        job.setTraceId(traceId);
        job.setCreatedBy(user.getId());
        job.setAgentId(query.getAgentId());
        job.setStatus("PENDING");
        job.setCreatedAt(new Date());
        jobMapper.insert(job);

        // 6. 同步 POST Python：等接单 200（SQLite 落库即入队），不等 pipeline。
        //    不用 @Async：接单秒级，再套异步是过度设计；失败当场暴露，不留空 PENDING。
        //    网络抖动由 Client 内重试（同一 jobId，最多 3 次）；这里不换号再打。
        try {
            pythonClient.createJob(jobId, traceId, task, context);
        } catch (Exception e) {
            job.setStatus("FAILED");
            job.setErrorMsg("python create failed");
            jobMapper.updateById(job);
            throw new ResearchUnavailableException("研究服务暂不可用");
        }

        return new CreateJobResponse(jobId, "PENDING");
    }

    private String buildContext(ChatQueryDO query) {
        // textResult + textSummary + 维度 + 指标，总长度 ≤ 4000 字
        StringBuilder sb = new StringBuilder();
        if (query.getTextResult() != null) {
            sb.append("## 查询结果\n").append(truncate(query.getTextResult(), 2000)).append("\n\n");
        }
        if (query.getTextSummary() != null) {
            sb.append("## 描述性解读\n").append(truncate(query.getTextSummary(), 1000)).append("\n\n");
        }
        // Demo 范围内只取 textResult + textSummary；维度/指标列表留作扩展
        // 未来从 ParseContext.getParsedS2SQL() 提取 metrics/dimensions 字段追加到 context
        return sb.toString();
    }
}
```

#### 6.3.3 `ResearchPermissionChecker` · 权限校验

```java
@Component
public class ResearchPermissionChecker {

    @Value("${research.enabled-admin-only:true}")
    private boolean adminOnly;

    @Value("${research.enabled-users:}")
    private Set<String> whitelist;

    @Value("${research.daily-quota:10}")
    private int dailyQuota;

    @Value("${research.max-concurrent-per-user:1}")
    private int maxConcurrent;

    @Autowired private ResearchJobMapper jobMapper;

    public void check(User user) {
        // 1. 功能权限（内测期：admin OR 白名单）
        boolean permitted = false;
        if (adminOnly && Integer.valueOf(1).equals(user.getIsAdmin())) {
            permitted = true;
        }
        if (whitelist.contains(user.getName())) {
            permitted = true;
        }
        if (!permitted) {
            throw new ResearchPermissionException(
                "深度研究功能内测中，仅对管理员开放");
        }

        // 2. 配额（每用户每日）
        int todayCount = jobMapper.countByUserAndDate(user.getId(), today());
        if (todayCount >= dailyQuota) {
            throw new ResearchQuotaExceededException("今日深度研究次数已用完");
        }

        // 3. 并发（每用户 max_concurrent 个未终态，即 PENDING）
        int runningCount = jobMapper.countByUserAndStatus(user.getId(), "PENDING");
        if (runningCount >= maxConcurrent) {
            throw new ResearchConcurrentException("已有深度研究进行中");
        }
    }

    public boolean isPermitted(User user) {
        // 轻量判断（不抛异常），用于 queryResult.researchFeature.enabled
        if (adminOnly && Integer.valueOf(1).equals(user.getIsAdmin())) return true;
        return whitelist.contains(user.getName());
    }

    public int remainingQuota(User user) {
        return Math.max(0, dailyQuota - jobMapper.countByUserAndDate(user.getId(), today()));
    }
}
```

#### 6.3.4 `PythonResearchClient` · 调 Python REST

创建接口写表后**同步**调用，等的是接单 `200`（含 IntentClassifier + SQLite INSERT，秒级），不是 pipeline。`RestTemplate` 必须设超时，避免 Python 假死把请求线程挂死。同一 `jobId` 遇到超时 / 连接拒绝 / **503** 时指数退避重试，最多 3 次（200 ms → 400 ms）；4xx 不重试。重试必须带**同一个** `jobId`：若第一次其实已经 INSERT 成功只是回包丢了，第二次会撞主键，Python 幂等回 `200`，不能换号再打。仍失败向上抛，由 `ResearchJobServiceImpl` 标 `FAILED` 并让创建失败。

用户权限已在 `createResearch` 做完。出站只带静态 `SERVICE_TOKEN`（与 Python 配置同一份），不转用户 JWT，不现签。见 §7.10。

```java
@Component
public class PythonResearchClient {

    private static final int MAX_ATTEMPTS = 3;
    private static final long BACKOFF_MS = 200; // 200 → 400，第三次失败不再等

    @Value("${research.python-base-url}")
    private String baseUrl; // Compose 内用服务名，如 http://research-agent:8000

    @Value("${research.service-token}")
    private String serviceToken; // 与 Python RESEARCH_SERVICE_TOKEN 同一份

    private final RestTemplate restTemplate = buildRestTemplate();

    private static RestTemplate buildRestTemplate() {
        SimpleClientHttpRequestFactory factory = new SimpleClientHttpRequestFactory();
        factory.setConnectTimeout(3000); // 连不上 3s 放弃，别把创建接口挂死
        factory.setReadTimeout(10000);   // 接单含本地 0.5B 分类 + INSERT，秒级足够
        return new RestTemplate(factory);
    }

    public void createJob(String jobId, String traceId,
                          String task, String context) {
        CreateJobRequest req = new CreateJobRequest();
        req.setJob_id(jobId); // Java 生成；重试仍带同一 id，Python 幂等
        req.setTrace_id(traceId);
        req.setTenant_id("default");
        req.setTask(task);
        req.setContext(context);
        req.setLength_budget(4000);
        req.setRetrieval_mode("hybrid");

        HttpHeaders headers = new HttpHeaders();
        headers.setBearerAuth(serviceToken); // Authorization: Bearer <SERVICE_TOKEN>
        headers.set("X-Trace-Id", traceId);
        headers.setContentType(MediaType.APPLICATION_JSON);

        HttpEntity<CreateJobRequest> entity = new HttpEntity<>(req, headers);
        executeWithRetry(() -> {
            restTemplate.postForEntity(
                baseUrl + "/v1/research/jobs", entity, String.class);
            return null;
        });
        // 2xx（含 200）即成功；4xx 不重试；网络抖动最多 3 次后向上抛
    }

    public PythonJobStatus getStatus(String jobId, boolean includeFull) {
        String url = baseUrl + "/v1/research/jobs/" + jobId;
        if (includeFull) url += "?include_full=true";

        HttpHeaders headers = new HttpHeaders();
        headers.setBearerAuth(serviceToken);

        return executeWithRetry(() -> {
            ResponseEntity<PythonJobStatus> resp = restTemplate.exchange(
                url, HttpMethod.GET,
                new HttpEntity<>(headers),
                PythonJobStatus.class
            );
            return resp.getBody();
        });
    }

    /** 只重试网络抖动（超时、连接拒绝）。4xx 再打也一样，立刻失败。 */
    private <T> T executeWithRetry(Supplier<T> action) {
        long backoff = BACKOFF_MS;
        for (int attempt = 1; attempt <= MAX_ATTEMPTS; attempt++) {
            try {
                return action.get();
            } catch (HttpClientErrorException e) {
                throw e;
            } catch (ResourceAccessException e) {
                if (attempt == MAX_ATTEMPTS) {
                    throw e;
                }
                try {
                    Thread.sleep(backoff);
                } catch (InterruptedException ie) {
                    Thread.currentThread().interrupt();
                    throw e;
                }
                backoff *= 2;
            }
        }
        throw new IllegalStateException("unreachable");
    }
}
```

#### 6.3.5 `ResearchSyncScheduler` · @Scheduled 同步（评审 #6 修复）

**核心改动**（对比原版）：
1. **isTimeout 用 `created_at`**（对齐 §4.4 决策 #7；Java 不存 RUNNING）
2. **`mergeStatus` 内置终态不可变校验**：本地已终态则拒绝 Python 回包覆盖；Python `RUNNING` 不写入 Java 表
3. **拉 Python 状态分两阶段**：先不带 full 拉状态；变 COMPLETED 后单独拉一次 full（修复评审 #10 的 `include_full` 恒 true bug）
4. **区分 404 与网络抖动**：404 立即标 FAILED（清理孤儿），网络抖动跳过下次重试（修复评审 #18）
5. **SSE 只在终态推**：Python 报 PENDING/RUNNING 时 Java 保持 PENDING，不推

```java
@Component
public class ResearchSyncScheduler {

    private static final Logger log = LoggerFactory.getLogger(ResearchSyncScheduler.class);
    private static final Set<String> TERMINAL = Set.of("COMPLETED", "FAILED");

    @Value("${research.timeout-minutes:15}")
    private int timeoutMinutes;

    @Autowired private ResearchJobMapper mapper;
    @Autowired private PythonResearchClient pythonClient;
    @Autowired private ResearchSseRegistry sseRegistry;

    @Scheduled(fixedDelayString = "${research.sync-interval-ms:2000}")
    public void syncRunningJobs() {
        List<ResearchJobDO> active = mapper.selectByStatusIn(
            Arrays.asList("PENDING"));

        for (ResearchJobDO job : active) {
            try {
                // 1. 超时兜底（Python 崩溃 / 网络分区），时钟 created_at
                if (isTimeout(job, timeoutMinutes)) {
                    flipToFailed(job, "java-side timeout after " + timeoutMinutes + " min");
                    continue;
                }

                // 2. 拉 Python 状态（不带 full）
                PythonJobStatus p = pythonClient.getStatus(job.getJobId(), false);

                // 3. 非终态：Java 保持 PENDING，不推 SSE
                if (!TERMINAL.contains(p.getStatus())) {
                    continue;
                }

                // 4. COMPLETED 时单独拉一次 full（评审 #10 修复）
                if ("COMPLETED".equals(p.getStatus())) {
                    PythonJobStatus full = pythonClient.getStatus(job.getJobId(), true);
                    p.setReportFull(full.getReportFull());
                }
                mergeStatus(job, p);   // 只写终态
            } catch (HttpClientErrorException.NotFound e) {
                flipToFailed(job, "python reports job not found (orphan record)");
            } catch (Exception e) {
                log.debug("[research] sync failed jobId={} will retry: {}",
                    job.getJobId(), e.getMessage());
            }
        }
    }

    /** 终态不可变合并：只写 COMPLETED/FAILED；RUNNING 不进 Java 表（评审 #6） */
    private void mergeStatus(ResearchJobDO job, PythonJobStatus p) {
        if (TERMINAL.contains(job.getStatus())) {
            log.warn("[research] reject terminal flip jobId={} local={} remote={}",
                job.getJobId(), job.getStatus(), p.getStatus());
            return;
        }
        if (!TERMINAL.contains(p.getStatus())) {
            return;   // PENDING/RUNNING：Java 保持 PENDING，不推 SSE
        }
        job.setStatus(p.getStatus());
        if (p.getStatus().equals("COMPLETED")) {
            job.setReportFull(p.getReportFull());
            job.setCompletedAt(new Date());
        } else if (p.getStatus().equals("FAILED")) {
            job.setErrorMsg(p.getErrorMsg());
            job.setCompletedAt(new Date());
        }
        mapper.updateById(job);
        sseRegistry.send(job.getJobId(), buildEvent(job));
        log.info("[research] status change jobId={} -> {}",
            job.getJobId(), p.getStatus());
    }

    /** 标 FAILED 并推 SSE；若本地已终态则跳过（幂等） */
    private void flipToFailed(ResearchJobDO job, String reason) {
        if (TERMINAL.contains(job.getStatus())) {
            return;   // 已终态，跳过（评审 #6）
        }
        job.setStatus("FAILED");
        job.setErrorMsg(reason);
        job.setCompletedAt(new Date());
        mapper.updateById(job);
        sseRegistry.send(job.getJobId(), buildEvent(job));
        log.warn("[research] timeout jobId={} traceId={}",
            job.getJobId(), job.getTraceId());
    }

    /** 超时时钟：created_at（§4.4 #7） */
    private boolean isTimeout(ResearchJobDO job, int minutes) {
        long elapsed = System.currentTimeMillis() - job.getCreatedAt().getTime();
        return elapsed > minutes * 60_000L;
    }
}
```

### 6.4 `ResearchSseRegistry` · SSE 推送（评审 #4 + #11 修复）

**核心改动**：
1. **`SseEmitter` 设有限超时**（20 分钟，略大于 job 15min 超时）——防资源耗尽（评审 #4c）
2. **终态推完后 `complete()`**——释放 emitter 资源（评审 #14）
3. **register 前归属校验已在 Controller 完成**——这里只信任已校验的调用方
4. **SSE 终态带 `report_full`**——报告硬上限 4000 字（约 12 KB），只推一次
5. **只推终态**——PENDING 不推；Python `RUNNING` 不写入 Java，也不推

```java
@Component
public class ResearchSseRegistry {

    private static final long SSE_TIMEOUT_MS = 20L * 60 * 1000;   // 20min，略大于 job 超时
    private static final Set<String> TERMINAL = Set.of("COMPLETED", "FAILED");

    @Autowired private ResearchJobMapper mapper;

    private final Map<String, List<SseEmitter>> emitters = new ConcurrentHashMap<>();

    public SseEmitter register(String jobId) {
        // 有限超时（评审 #4c 修复）
        SseEmitter emitter = new SseEmitter(SSE_TIMEOUT_MS);
        emitters.computeIfAbsent(jobId, k -> new CopyOnWriteArrayList<>())
                .add(emitter);

        emitter.onCompletion(() -> remove(jobId, emitter));
        emitter.onTimeout(() -> {
            remove(jobId, emitter);
            log.debug("[research] SSE timeout jobId={}", jobId);
        });
        emitter.onError(e -> remove(jobId, emitter));

        // 首次连接立即推当前状态（避免新连接看不到状态）
        ResearchJobDO current = mapper.selectById(jobId);
        if (current != null) {
            try {
                emitter.send(SseEmitter.event().data(buildEvent(current)));
                // 已终态立即 complete，释放资源（评审 #14）
                if (TERMINAL.contains(current.getStatus())) {
                    emitter.complete();
                }
            } catch (IOException ignored) {}
        }
        return emitter;
    }

    public void send(String jobId, Object event) {
        List<SseEmitter> list = emitters.get(jobId);
        if (list == null) return;
        for (SseEmitter e : list) {
            try {
                e.send(SseEmitter.event().data(event));
                // 推送终态后 complete（评审 #14）
                if (event instanceof JobStatusResponse rs
                        && TERMINAL.contains(rs.getStatus())) {
                    e.complete();
                }
            } catch (IOException ex) {
                remove(jobId, e);
            }
        }
    }

    private void remove(String jobId, SseEmitter emitter) {
        emitters.computeIfPresent(jobId, (k, v) -> {
            v.remove(emitter);
            return v.isEmpty() ? null : v;
        });
    }

    /** SSE 推送 payload：终态带这一份 report_full（≤4000 字） */
    private JobStatusResponse buildEvent(ResearchJobDO job) {
        return new JobStatusResponse(
            job.getJobId(), job.getQueryId(),
            job.getStatus(),
            job.getReportFull(),
            job.getErrorMsg()
        );
    }
}
```

```python
# server/rest/report_store.py
from pathlib import Path
import json
from typing import Protocol

class ReportStore(Protocol):
    def save(self, job_id: str, tenant_id: str, payload: dict) -> str: ...
    def get(self, job_id: str, tenant_id: str = "default") -> dict | None: ...
    def delete(self, job_id: str, tenant_id: str = "default") -> None: ...

class FileSystemReportStore:
    """当前实现：JSON 文件存到 outputs/{tenant_id}/research_jobs/{job_id}.json

    设计动机：
    - JSON 含结构化字段（report_markdown + boxed_answer + metadata），未来迁移 MongoDB/PostgreSQL JSONB 格式不变
    - 按 tenant 分目录，未来多租户自然隔离
    - 开发者可直接打开 JSON 文件调试
    """

    def __init__(self, base_dir: str = "outputs"):
        self.base_dir = Path(base_dir)

    def _path_for(self, tenant_id: str, job_id: str) -> Path:
        return self.base_dir / tenant_id / "research_jobs" / f"{job_id}.json"

    def save(self, job_id: str, tenant_id: str, payload: dict) -> str:
        path = self._path_for(tenant_id, job_id)
        path.parent.mkdir(parents=True, exist_ok=True)
        path.write_text(
            json.dumps(payload, ensure_ascii=False, indent=2),
            encoding="utf-8"
        )
        return f"fs://{path}"

    def get(self, job_id: str, tenant_id: str = "default") -> dict | None:
        path = self._path_for(tenant_id, job_id)
        if not path.exists():
            return None
        return json.loads(path.read_text(encoding="utf-8"))

    def delete(self, job_id: str, tenant_id: str = "default") -> None:
        path = self._path_for(tenant_id, job_id)
        if path.exists():
            path.unlink()
```

### 7.4 IntentClassifier（路由分类 · 本地 0.5B）

**职责**：在 FastAPI 进程内用 **Qwen2.5-0.5B-Instruct** 做三分类（约 50ms、<1GB 显存）。worker **不**加载这颗模型。失败统一 fallback `default`，照常 INSERT。

**输入**：请求体 `query` 原样（Java 已按表 2000 / 解读 1000 / 整段 4000 截断）。Python 不再切。

**模型 JSON → 落库**：

| 模型 `label` | SQLite `research_type` |
| --- | --- |
| `financial_analysis` | `financial_analyst` |
| `academy_research` | `academic` |
| `default` | `default` |

**不输出、不落库 `data_domain`。** 分类器只决定研究范式。领域框架交给 14 分钟大模型。删列与 enhance 口径见面试稿 §5.3 Q2。

**System prompt**：

```
你是一个文本分类器。你的任务是根据用户输入的自然语言内容，将其划分为以下三类之一：
- financial_analysis：与金融分析、市场数据、财务报表、投资分析等相关
- academy_research：与学术研究、论文、理论推导、实验设计、文献综述等相关
- default：不属于以上两类的其他内容

只有用户明确要走金融分析或学术研究范式时才输出前两类；看表算数、归因、解释问数结果但没有指定范式时，输出 default。不确定时必须输出 default。

你必须且只能输出一个合法的 JSON 对象，格式如下：
{"label": "financial_analysis" | "academy_research" | "default"}

不要输出任何额外文字、解释或标记。
```

User 即 `{query}`。若模型包了 markdown 代码围栏，解析层剥掉再读；仍坏则 `default`。

```python
# server/rest/intent.py
LABEL_TO_TYPE = {
    "financial_analysis": "financial_analyst",
    "academy_research": "academic",
    "default": "default",
}

class IntentClassifier:
    """进程内 0.5B 三分类。加载失败时 classify 仍返回 default。"""

    async def classify(self, query: str) -> str:
        try:
            raw = await self._complete(query)  # 本地 0.5B
            data = _parse_label_json(raw)
            return LABEL_TO_TYPE.get(data.get("label"), "default")
        except Exception:
            return "default"
```

**为什么分类和改写分离**：分类失败只 fallback type，不污染 query；改写失败只用原文，不改 type。pipeline 超时才 `UPDATE FAILED`。

**为什么用 `financial_analyst` 而不是 `industry`**：原 `industry` 过窄；落库名保持分析师视角，模型 label 用 `financial_analysis`。

### 7.5 ResearchDirective（type-specific 研究指导 prompt）

**职责**：根据 IntentClassifier 输出的 type，加载对应的 Markdown 提示词模板，作为**研究指导**拼到 task description 前面。原 query 保持不变——这是"加约束"而非"改意图"。

> **面试口径：Intent 路由 ≈ query enhance，不是换 Main 角色类。** 分类出三种 type 后，ResearchDirective 把对应研究指导 **prepend 进本条 task**；Main 仍用配置里钉死的 `prompt_class`。金融不再按 `data_domain` 拼片段。入口衔接见 [`03` §1.2](./03-Main-Sub-Agent编排.md#12-上游衔接用户-query-如何进到-mainsub)。

**为什么不直接改写 query**：
- 改写会改变用户意图（"比亚迪 2024 净利润"被改成"比亚迪 2024 净利润 行业对比"已经偏题）
- 不同风格的差异本质是"Agent 关注点不同"，不是"用户问题不同"
- 用 ResearchDirective 指导 Agent 怎么研究，比改用户问题更稳

**模板文件位置**：`server/rest/research_prompts/{type}.md`

#### `financial_analyst.md`（金融分析师核心框架 · 四步归因法）

**定位说明**：本文件是**通用金融分析核心框架**——四步归因法 + 证据强度 + 报告结构。不再按 `data_domain` 外挂 `domains/*.md`；领域口径由 pipeline 大模型从 query 里自己选。加新研究风格 = 加一套 type md + 分类 label。

```markdown
你是一名**金融分析师**（兼具金融经济研究、财报分析、宏观归因视角）。
本研究的核心目标：**对查询结果做深度归因与预测**——不只是描述数据，
要回答"为什么是这个值"、"接下来会怎样"。

## 分析四步法（任何数据都必须完整走）

### 第一步：数据描述（是什么）
- 报告核心数字 + 时间口径（年报 / 季报 / 月度）
- 横向锚定：同比 / 环比 / 与同行 / 与行业平均 / 与历史区间
- 结构分解：按业务线 / 区域 / 客户群 / 产品类别
- **不要堆数据**——提炼**关键变化点**（什么涨了、什么跌了、什么反常）

### 第二步：归因分析（为什么）—— 核心能力，篇幅最大
列出所有可能的驱动因素，**每个因素标注证据强度**：

- **业务驱动**：销量 / 价格 / 成本 / 结构调整 / 一次性事件
- **行业驱动**：周期位置 / 供需变化 / 技术变革 / 竞争格局
- **宏观驱动**：GDP / 利率 / 汇率 / 政策 / 国际环境
- **领域特有驱动**：由大模型根据 query 自行选择框架（杜邦 / 碳 / 五力等），不靠分类标签

**证据强度标注**（强制）：
- **[已验证]**：查询结果或公开数据直接支持
- **[推断]**：行业逻辑或类比推导，未直接验证
- **[推测]**：合理假设但缺证据，必须明确假设条件

### 第三步：预测分析（会怎样）
- **短期（下一报告期）**：基于动量、基数、已知事件
- **中期（1-3 年）**：基于核心驱动因素的持续性判断
- **情景分析**：base / bull / bear 三种情景的关键假设与概率权重
- **不强行给精确目标值**——预测的核心是**展示驱动逻辑与假设敏感度**

### 第四步：不确定性与风险
- 数据口径限制（未经审计、口径变更、样本偏倚）
- 归因置信度（哪些驱动是高把握，哪些是低把握）
- 预测的关键假设（哪些假设变化会颠覆结论）
- **反面证据**（不支持当前归因的数据，必须列出，不选择性忽略）

## 何时不做估值（强制约束）

**只有当"数据领域片段"显式启用估值方法时**，才使用 DCF / 可比公司等。
默认情况下（无领域片段，或片段未启用估值）**严禁套估值模型**——
归因分析 + 预测分析才是核心。

## 数据与时间口径（不可违反）

- 每个数字必须能链回数据源：查询结果 / 财报原文 / Wind / Bloomberg / 国家统计局 / 行业协会
- **严禁编造数据**：找不到就写"未公开披露"或"估算（注明假设）"
- 时间口径必须明确：年报 / 季报 / 业绩预告 / 业绩快报 / 月度 / 季度 不能混用
- 同比 / 环比要说明基数

## 报告结构（强制，适配任何数据域）

```
1. 数据要点（核心数字 + 关键变化点，一页内）
2. 归因分析（驱动因素 + 证据强度标注）         ← 篇幅最大，至少占全文 40%
3. 预测与情景（短期 / 中期 + base / bull / bear）
4. 不确定性与风险（含反面证据）
5. 结论（基于证据强度的整体判断）
```

## 禁止行为

- ❌ 编造数据或引用未公开披露数字
- ❌ **强行套估值模型**（数据领域片段未显式启用时）
- ❌ 归因不标证据强度
- ❌ 预测不给假设条件
- ❌ **只描述不归因**（"营收增长 20%"远远不够，必须回答"为什么增长 20%"）
- ❌ 隐藏不确定性或反面证据
- ❌ 对推测性结论不标注置信度
```

### 7.6 QueryRewriter（仅 default，外部 chat API）

`financial_analyst` / `academic` 有范式 md，不改 query。`default` 在 **worker** 里用 **pipeline 同一套 chat 客户端** 把整段 `query` 改写成研究任务表述，再交给 ResearchDirective 拼 `default.md`。

- 短超时 `REWRITE_TIMEOUT_S = 20`，禁止套 14 分钟 pipeline 硬超时。
- 超时 / 5xx / 空回包 → 原文，**不** `UPDATE FAILED`。
- 不挡 200；结果不回写 SQLite；报告 JSON 可留 `rewritten_query`。

```python
# server/rest/query_rewriter.py
import asyncio

REWRITE_TIMEOUT_S = 20

class QueryRewriter:
    def __init__(self, llm_client):
        self.llm_client = llm_client  # 与 pipeline 同一套

    async def rewrite(self, query: str, research_type: str) -> str:
        if research_type != "default":
            return query
        try:
            text = await asyncio.wait_for(
                self.llm_client.complete(rewrite_prompt(query)),
                timeout=REWRITE_TIMEOUT_S,
            )
            return (text or "").strip() or query
        except Exception:
            return query
```

### 7.7 长度控制（三层级联）

```python
# server/rest/length_control.py
import re

SENTENCE_BOUNDARY = re.compile(r'(?<=[。！？\n])')

def enforce_length_budget(report: str, budget: int = 4000) -> str:
    """句子边界感知截断

    设计原则：
    - Prompt 软引导（task description 内已要求 length_budget 字数）
    - 产出后硬兜底（此处）：按句子边界截断，不破坏内容
    - 允许 20% 浮动，避免勉强
    """
    if len(report) <= int(budget * 1.2):
        return report

    parts = SENTENCE_BOUNDARY.split(report)
    result, total = [], 0
    for p in parts:
        if total + len(p) > budget:
            break
        result.append(p)
        total += len(p)

    summary = "".join(result).rstrip()
    if len(summary) < len(report):
        summary += "\n\n…（已省略部分细节，完整报告见 report_full）"
    return summary
```

### 7.8 pipeline_adapter.py · 异步执行包装（含路由后处理 + 硬超时）

```python
# server/rest/pipeline_adapter.py
import asyncio
import logging
import pathlib
from datetime import datetime, timezone
from .job_store import JobStore
from .report_store import FileSystemReportStore
from .length_control import enforce_length_budget
from .research_directive import ResearchDirective
from .query_rewriter import QueryRewriter
from .pipeline_timeout import PipelineTimeoutError, run_with_timeout
from ..bridge.config_loader import compose_config, create_pipeline_components
from src.core.pipeline import execute_task_pipeline

logger = logging.getLogger("server.rest.pipeline_adapter")
report_store = FileSystemReportStore()
directive = ResearchDirective()

# Python 硬超时（评审 #6 修复）：必须早于 Java 15min 兜底
PIPELINE_HARD_TIMEOUT_S = 14 * 60   # 14 分钟

async def run_pipeline_async(
    job_id: str, query: str,
    research_type: str, config_name: str, trace_id: str,
    tenant_id: str, length_budget: int,
    job_store: JobStore, llm_client,
):
    from .logging_config import set_trace_id
    set_trace_id(trace_id)

    # 幂等保护：若 Job 已终态（如启动恢复标过 FAILED），直接返回
    current = job_store.get(job_id)
    if current and current.status in {"COMPLETED", "FAILED"}:
        logger.warning(f"job {job_id} already terminal, skip",
                       extra={"trace_id": trace_id})
        return

    job_store.update(job_id,
        status="RUNNING",
        started_at=datetime.now(timezone.utc).isoformat(),
    )

    try:
        # 1. QueryRewriter：仅 default 调 chat API（20s）；失败用原文
        rewritten_query = await QueryRewriter(llm_client).rewrite(query, research_type)

        # 2. ResearchDirective：按 type 拼范式 md
        full_task = directive.compose_task(
            research_type=research_type,
            user_task=rewritten_query,
            length_budget=length_budget,
        )

        # 3. 调用现有 execute_task_pipeline（用 asyncio.wait_for 包装硬超时）
        cfg = compose_config(config_name)
        components = create_pipeline_components(cfg)

        final_answer, boxed_answer, log_path = await run_with_timeout(
            execute_task_pipeline(
                cfg=cfg,
                task_name=job_id,
                task_id=job_id,
                task_description=full_task,
                task_file_name=None,
                main_agent_tool_manager=components[0],
                sub_agent_tool_managers=components[1],
                output_formatter=components[2],
                log_path=pathlib.Path("logs") / f"{job_id}.json",
                ground_truth=None,
                metadata={"trace_id": trace_id, "source": "rest_api",
                          "research_type": research_type},
                event_sink=None,
                human_interaction=None,
            ),
            timeout_s=PIPELINE_HARD_TIMEOUT_S,
            job_id=job_id,
        )

        # 4. 长度控制：句子边界截断
        summary = enforce_length_budget(final_answer, budget=length_budget)

        # 5. 完整报告写 JSON 文件
        report_uri = report_store.save(job_id, tenant_id, {
            "job_id": job_id,
            "trace_id": trace_id,
            "task": query,
            "research_type": research_type,
            "rewritten_query": rewritten_query if rewritten_query != query else None,
            "report_markdown": final_answer,
            "boxed_answer": boxed_answer,
            "metadata": {
                "config_file_name": config_name,
                "model_used": cfg.get("main_agent", {}).get("model", "unknown"),
            },
            "created_at": datetime.now(timezone.utc).isoformat(),
            "completed_at": datetime.now(timezone.utc).isoformat(),
        })

        # 6. SQLite 只存 summary + URI（终态不可变校验在 job_store.update 内）
        job_store.update(job_id,
            status="COMPLETED",
            report_uri=report_uri,
            completed_at=datetime.now(timezone.utc).isoformat(),
        )
        logger.info(f"job {job_id} completed type={research_type}",
                    extra={"trace_id": trace_id})

    except PipelineTimeoutError as e:
        job_store.update(job_id,
            status="FAILED",
            error_msg=f"python hard timeout after {PIPELINE_HARD_TIMEOUT_S}s",
            completed_at=datetime.now(timezone.utc).isoformat(),
        )
        logger.warning(f"job {job_id} timeout", extra={"trace_id": trace_id})

    except asyncio.CancelledError:
        # 启动恢复 / 显式 cancel 时进入此分支；不覆盖已终态状态
        current = job_store.get(job_id)
        if not current or current.status not in {"COMPLETED", "FAILED"}:
            job_store.update(job_id,
                status="FAILED",
                error_msg="task cancelled",
                completed_at=datetime.now(timezone.utc).isoformat(),
            )
        raise   # propagate

    except Exception as e:
        job_store.update(job_id,
            status="FAILED",
            error_msg=f"{type(e).__name__}: {str(e)[:500]}",
            completed_at=datetime.now(timezone.utc).isoformat(),
        )
        logger.exception(f"job {job_id} failed", extra={"trace_id": trace_id})
```

**`pipeline_timeout.py` 实现**：

```python
# server/rest/pipeline_timeout.py
import asyncio
from typing import Awaitable, TypeVar

T = TypeVar("T")

class PipelineTimeoutError(Exception):
    """Pipeline 硬超时，Python 侧权威超时信号"""

async def run_with_timeout(
    coro: Awaitable[T], timeout_s: int, job_id: str,
) -> T:
    task = asyncio.ensure_future(coro)
    try:
        return await asyncio.wait_for(task, timeout=timeout_s)
    except asyncio.TimeoutError:
        task.cancel()
        try:
            await task   # let cleanup run
        except (asyncio.CancelledError, Exception):
            pass
        raise PipelineTimeoutError(f"{job_id} exceeded {timeout_s}s")
```

**关键设计点**：

1. **ResearchDirective 调用在 try 外**：若 prompt 模板加载失败，不应进入 RUNNING 状态——但实际通过 `lru_cache + default fallback` 已避免
2. **`rewritten_task` 写入 report JSON**：审计可追溯，区分原 task 和实际执行的 task
3. **`except PipelineTimeoutError` 单独分支**：error_msg 明确"python hard timeout"，与 Java 兜底区分
4. **`except asyncio.CancelledError` 幂等**：不覆盖已终态，符合 §4.3 终态不可变约束

```python
TERMINAL_STATUSES = frozenset({"COMPLETED", "FAILED"})

class JobStore:

        self._init_schema()

    def update(self, job_id: str, status: str | None = None, **fields):
        """终态不可变校验：COMPLETED/FAILED 一旦写入，任何 status 覆盖都被拒绝

        评审 #6 修复：防止 Java 超时标 FAILED 后 Python 回包 COMPLETED 造成永久分叉。
        业务字段（如 report_summary/error_msg）更新允许，但 status 不可反向迁移。
        """
        if status is not None:
            current = self.get(job_id)
            if current and current.status in TERMINAL_STATUSES and status != current.status:
                logger.warning(
                    f"reject status flip job={job_id} "
                    f"{current.status} -> {status}",
                    extra={"trace_id": current.trace_id},
                )
                return False   # 调用方可记录，但视为成功幂等
        # 执行真实 UPDATE（带 status 守卫的 SQL）
        return self._do_update(job_id, status=status, **fields)

    HEARTBEAT_STALE_S = 120

    def claim_one_pending(self):
        """CAS：把最早一条 PENDING 改成 RUNNING。0 行表示队列空。"""
        now = datetime.now(timezone.utc).isoformat()
        return self._execute_returning("""
            UPDATE research_jobs
            SET status = 'RUNNING', started_at = ?, heartbeat_at = ?, updated_at = ?
            WHERE job_id = (
                SELECT job_id FROM research_jobs
                WHERE status = 'PENDING'
                ORDER BY created_at
                LIMIT 1
            )
            RETURNING *
        """, (now, now, now))

    def recover_stale_jobs(self):
        """worker 启动：只收心跳已死的 RUNNING。PENDING 还在表里，claim 会取，不能标失败。"""
        stale = self.list_running_with_stale_heartbeat(self.HEARTBEAT_STALE_S)
        for job in stale:
            self._do_update(job.job_id,
                status="FAILED",
                error_msg="worker heartbeat lost",
                completed_at=datetime.now(timezone.utc).isoformat(),
            )
            logger.warning(
                f"recovered stale job {job.job_id}",
                extra={"trace_id": job.trace_id},
            )
```

worker 跑 pipeline 期间每 30s 写 `heartbeat_at`。收尸只由 **worker 进程**调用：启动扫一次，之后 poll 循环每 30s 再扫；只处理心跳超过 15 分钟的 `RUNNING`。FastAPI 重启**不**扫、也**不**收尸：`PENDING` 还在表里，worker 下次 claim 会取。立刻重启不够——心跳还新，要等 15 分钟窗口。一台机器只跑一个 worker，避免多进程抢同一 SQLite。

### 7.10 静态 SERVICE_TOKEN（相等校验，不复用 SuperSonic 用户 JWT）

用户权限（归属、开关、配额、并发）在 Java 出站前已经做完。Python 不认用户，出站 token 只证明「调用方是问数网关」。

**怎么定义。** 运维生成一次高熵随机串（`openssl rand -hex 32`），写入环境变量 `RESEARCH_SERVICE_TOKEN`。Compose 从宿主机 `.env`（gitignore）注入两边；仓库、镜像、`application.yml` 不写真实值。本地可留一眼假的默认值，生产读到默认值则拒绝启动。轮换时两边同时换新值再滚动重启。

**为什么还要 token。** Java 和 Python 放进同一个 Compose 项目。Compose 默认建一张网，容器用服务名互访（如 `http://research-agent:8000`），不必写死 IP。[Compose 网络](https://docs.docker.com/compose/how-tos/networking/)：服务名进内部 DNS，同网络里谁都能解析到谁。对外只映射 Java 端口，浏览器进不了这张网；**同网络里别的容器却能按服务名打到 Python**。所以两边配置同一份 `RESEARCH_SERVICE_TOKEN`，Java 带 `Authorization: Bearer <token>`，Python 只做字符串相等——挡住「任意内部容器都能调」，不改调用架构。

**为什么不转用户 JWT、不现签：**
- 用户 JWT payload 含 `token_user_password`（密码哈希），跨服务会泄漏
- 登录密钥一旦给 Python，两个服务绑死
- 现签短时 JWT / OAuth / mTLS 不增加权限边界，只是把已鉴过权的调用再包一层

```python
# server/rest/deps.py
import os
from fastapi import Header, HTTPException

SERVICE_TOKEN = os.getenv("RESEARCH_SERVICE_TOKEN", "")

async def verify_service_token(authorization: str = Header(...)) -> bool:
    expected = f"Bearer {SERVICE_TOKEN}"
    if authorization != expected:
        raise HTTPException(401, "invalid service token")
    return True
```

```python
# server/rest/routes.py
from sqlite3 import IntegrityError, OperationalError
from fastapi import APIRouter, Depends, HTTPException
from .deps import verify_service_token

router = APIRouter()

@router.post(
    "/v1/research/jobs",
    status_code=200,
    dependencies=[Depends(verify_service_token)],
)
async def create_job(req: CreateJobRequest):
    research_type = await intent_classifier.classify(req.query)

    try:
        job_store.create(
            job_id=req.job_id,
            tenant_id=req.tenant_id or "default",
            trace_id=req.trace_id,
            query=req.query,
            research_type=research_type,
            status="PENDING",
        )
    except IntegrityError:
        existing = job_store.get(req.job_id)
        if existing is None:
            raise HTTPException(500, "job_id conflict but row missing")
        # Java 同 job_id 重试：行已经在，入队已成功，不能 503
        return {"job_id": existing.job_id, "status": existing.status}
    except OperationalError:
        raise HTTPException(503, "research store unavailable")

    return {"job_id": req.job_id, "status": "PENDING"}
```

`INSERT PENDING` 成功即入队。磁盘满 / 锁超时：库里没有行，回 503，Java 把**本地**行标 FAILED。主键冲突：第一次已经写进去，回 200，Java 当成功。不要为入队失败再 INSERT 一条 Python `FAILED`。

```python
# server/rest/worker.py
import asyncio
from .job_store import job_store
from .pipeline_adapter import run_pipeline_async

CONCURRENCY = 4
POLL_INTERVAL_S = 0.5

async def run_one(job):
    config_name = TYPE_TO_CONFIG.get(job.research_type, "agent_llm_gpt5")
    await run_pipeline_async(
        job_id=job.job_id,
        query=job.query,
        research_type=job.research_type,
        config_name=config_name,
        trace_id=job.trace_id,
        tenant_id=job.tenant_id,
        length_budget=4000,
        job_store=job_store,
        llm_client=None,
    )

async def main():
    job_store.recover_stale_jobs()
    sem = asyncio.Semaphore(CONCURRENCY)
    inflight: set[asyncio.Task] = set()

    async def guarded(job):
        async with sem:
            await run_one(job)

    while True:
        if len(inflight) < CONCURRENCY:
            job = job_store.claim_one_pending()
            if job:
                task = asyncio.create_task(guarded(job))
                inflight.add(task)
                task.add_done_callback(inflight.discard)
                continue
        await asyncio.sleep(POLL_INTERVAL_S)

if __name__ == "__main__":
    asyncio.run(main())
```

Compose 里 FastAPI 与 `python -m server.rest.worker` 并列，共享同一份 SQLite。执行并发用 Semaphore 封顶，不靠多 worker 进程抢文件。

## 8. 权限控制（Java 侧实现）

### 8.1 设计原则

**权限完全在 Java，Python 不感知用户**：
- Python 只验证 SERVICE_TOKEN（防同网络旁路调用；不含用户身份）
- Python 不需要 user_id / agent_id / 权限规则

**层次划分**：

| 层 | 关心 | 不关心 |
|----|------|--------|
| Python | tenant + job 执行 | user、agent、权限规则 |
| Java | user（权限）+ agent（业务上下文）+ job（路由） | 报告内部内容 |

| 阶段 | 权限判断方式 | 改动 |
|------|-------------|------|

### 8.5 关键澄清：权限信息 vs 审计信息

| 类型 | 存哪 | 例子 |
|------|------|------|
| **权限信息**（运行时判断） | 不存表，运行时从 user 对象 + 配置读 | "alice 是 admin 吗？" |
| **审计信息**（事后追溯） | 存 `s2_chat_research_job.created_by` | "job X 是 alice 触发的" |
| **配额统计**（运行时聚合） | 不专门存，从审计表聚合 | "alice 今天用了几次？" |

**不存权限表**：内测阶段权限规则简单（isAdmin），存表是过度设计。

## 9. 错误处理 + 可观测性 + 测试

### 9.1 错误处理矩阵（对齐评审 #6 / #18 修复）

| # | 失败点 | Python 状态 | Java 响应 | 前端表现 |
|---|--------|------------|-----------|---------|
| 1 | 创建时 Python 挂了 / 超时 | 无响应或非 2xx | 标 FAILED，创建接口 **503** | 不进入 loading，可重试 |
| 1b | 已接单后 Python 进程挂了 | 无响应 | GET 失败当抖动跳过；15min 兜底标 FAILED | 继续 loading → 最终静默隐藏 |
| 2 | pipeline 抛异常 | FAILED + error_msg | `mergeStatus` 标 FAILED + 推 SSE | return null（静默） |
| 3 | IntentClassifier 失败 | fallback `default` | Java 保持 PENDING | 正常完成 |
| 4 | LLM 调用失败 | pipeline 抛异常 → FAILED | 同 #2 | 静默 |
| 5 | 报告文件写入失败 | pipeline 抛异常 → FAILED | 同 #2 | 静默 |
| 6 | 创建时 SQLite 磁盘满 / 锁超时 | **无行**，HTTP 503 | 标 FAILED，创建接口 **503** | 不进入 loading |
| 6b | 创建回包丢失，同 job_id 再 POST | 主键冲突 → **仍 200**（行已在） | 当成成功，保持 PENDING | 转圈，worker 会跑 |
| 7 | Java→Python 网络抖动（拉状态） | - | GET 抛非 404，**跳过本次，下次再试**（评审 #18） | 继续 loading（用户无感） |
| 8 | 创建时 Service token 不匹配 | HTTP 401 | 标 FAILED，创建接口 **503** + 严重告警 | 不进入 loading |
| 9 | Job 不存在（Python 重启清库） | HTTP 404 | `HttpClientErrorException.NotFound` → 立即 FAILED（评审 #18） | 静默 |
| 10 | worker 进程重启 | 只把心跳已死的 RUNNING 标 FAILED；PENDING 仍在表里 | Java 拉到 FAILED，推 SSE | 静默 |
| 11 | **Python 硬超时（14min）**（评审 #6） | `wait_for` 触发，标 FAILED | 拉到 FAILED，推 SSE | 静默 |
| 12 | **Java 兜底超时（15min）**（评审 #6） | Python 已 COMPLETED 但 Java 未拉到 | `flipToFailed` 标 FAILED；后续 Python 回包**被拒绝**（终态不可变） | 静默 |
| 13 | **越权访问 jobId**（评审 #4） | 正常返回 | `ResearchOwnershipChecker` 抛 `ResearchNotFoundException`（不泄露存在性） | 前端显示"未找到" |

**核心原则**（对齐 B5）：
- 创建接口失败（503）→ 前端不进入研究态，可重试
- 已经开始的研究失败 → 前端 `return null`（保留 textSummary）
- 失败原因**永远**写日志（带 traceId）
- 不弹 toast、不覆盖 textSummary
- **终态不可变**（评审 #6）：一旦 COMPLETED/FAILED，任何反向状态迁移都被拒绝（Python `JobStore.update` + Java `mergeStatus` + SQL `WHERE status NOT IN (...)` 三层守卫）

## 10. 三个演进锚点

整个设计的核心原则：**协议先就绪、实现可渐进**。三个关键演进锚点：

### 10.1 路由（无数据域列）

- **协议就绪**：POST body 不传 `research_type`，Python 全权决策
- **当前实现**：
  - FastAPI 进程内 Qwen2.5-0.5B 输出 `{label}`，映射为 `research_type`
  - 三类 type 仍落到同一套 `agent_llm_gpt5`（pipeline config 未分化）
  - **不存 `data_domain`**，不拼 `domains/*.md`
  - `default` 在 worker 用 pipeline 同一套 chat API 改写（20s）
- **演进触发**：加新研究风格（如 medical）→ 加 `medical.md` + 分类 label
- **演进成本**：不动协议、Java、前端；不加领域列
- **未来**：按 type 真正分 agent config；0.5B 可换成 1.5B 若三分类不稳

### 10.2 报告存储

- **协议就绪**：`report_uri` 字段通用（`fs://` / `mongo://` / `pg://`）
- **当前实现**：`FileSystemReportStore` 存 JSON 到 `outputs/{tenant}/research_jobs/{job_id}.json`
- **演进触发**：生产化部署时
- **演进成本**：换实现类（`MongoReportStore` / `PgJsonbReportStore`），序列化格式（JSON）不变，URI scheme 换掉

### 10.3 多租户

- **协议就绪**：`tenant_id` 进 schema 和 REST 协议，缺省 `"default"`
- **当前实现**：所有 job 属 `"default"`，不实现隔离逻辑（按 `job_id` 主键查天然隔离）
- **演进触发**：加列表查询接口或真实多租户部署时
- **演进成本**：Java 把 agentId 映射到 tenant_id；Python GET 加 `WHERE tenant_id = ?` 过滤；ReportStore 已按 tenant 分目录

**三者共同的设计原则**：Demo 阶段每项只做最小实现，但字段和抽象接口先留好，未来演进无损。

## 12. 面试讲解话术（整合）

### 12.1 整体架构

> "Java 是网关，Python 是研究中心。Java 负责权限、组装上下文、写表后同步向 Python 接单；Python 负责意图识别、SQLite 落库即入队、独立 worker 扫表跑 pipeline、产出报告。创建接口等的是接单 200（库里有 PENDING 行），不是研究报告。两个独立方向：Java→Python 用 @Scheduled 主动拉，流量与用户数解耦；Java→前端用 SSE 推送，避免无效轮询。"

### 12.2 三个演进锚点

> "协议先就绪、实现可渐进：
>
> 1. **路由**：Python IntentClassifier 全权分类，加新研究类型不动协议
> 2. **报告存储**：ReportStore Protocol 抽象，当前 FileSystemReportStore，未来换 MongoDB 或 PostgreSQL JSONB 不动协议
> 3. **多租户**：tenant_id 字段进 schema 和协议，当前 Demo 不实现隔离（按 jobId 主键查天然隔离），未来加列表接口时补 WHERE 过滤
>
> 三者共同的设计原则是 Demo 阶段每项只做最小实现，但字段和抽象接口先留好。"

### 12.3 权限边界

> "权限完全在 Java 网关——Python 不感知用户体系。Java 在 POST 之前做三层校验：功能开关（用户 JWT 的 isAdmin 字段 + 白名单）、每日配额、并发数。校验通过才调 Python，出站带静态 `SERVICE_TOKEN`（`Authorization: Bearer`）。
>
> Compose 默认网络按服务名互访，同网络容器都能打到 Python，所以 token 相等校验挡住旁路调用，不改调用架构。**不转发 SuperSonic 用户 JWT**：payload 含密码哈希；登录密钥会耦合。现签短时 JWT 不增加权限边界，这里不做。"

### 12.4 失败处理

> "失败的核心契约是'静默保留 textSummary'——10 种失败场景（Python 异常、Python 重启、网络抖动、配额耗尽、权限拒绝、token 错、SSE 断线等）全部走相同路径：前端 return null，不渲染任何东西；失败原因进日志（带 traceId）。
>
> Python 侧 SQLite 即队列。Worker 重启只收心跳已死的 RUNNING；PENDING 还在表里，下次 claim 会取，不能一律标失败。执行并发用 Semaphore(4) 封顶。Java 下次轮询秒级感知。Java 侧 15 分钟超时兜底防假死。"

### 12.5 可观测性

> "三层可观测性：
>
> 1. **结构化日志**：Java logback + Python logging，统一带 trace_id（HTTP header 透传），事后用单条 grep 命令串起完整调用链
> 2. **TaskTracer JSON**：Python 侧已有，每次 LLM 调用前后写完整 message_history 到文件，调试时直接打开看
> 3. **业务状态表**：Java `s2_chat_research_job` 是事实来源，任何状态机变化都落表
>
> 测试三层：单测（JUnit/pytest/Jest）+ 集成（SpringBootTest + FastAPI TestClient）+ E2E（Puppeteer，可选）。"
