# 指标口径：耗时、Token、费用

> 智能问数和深度研究的数字集中在这一篇。效果类指标（端到端 45%→87%、GAIA-165 53%）不在这里，分别见 [智能问数/01](./智能问数/01-总览与业务背景.md)、[深度研究/01](./深度研究/01-通用问答.md)。
>
> 开口只讲下面三句和对照表。追问再翻分表。两套系统的模型、样本、统计方式都不同，不能相加，也不能拿一个的单价去乘另一个的 token。

---

## 0. 开口前的三条红线

1. **问数的 token 有三层，不要合成一个数。** 线上整链常见 **4k–10k**；全开三步的构成估算是 **入 9.5k / 出 0.73k**（落在区间上沿）；日志里单独一条 **~1520** 是某次 S2SQL 主调用，不是整链。
2. **深度研究只报跑完的 3 题**（2026-08-09，`step_logs` 墙钟 + `usage_calculation` 加总）。平均、P95、P99 都来自这 3 题，P95/P99 贴着最慢那条。
3. **费用都是按刊例反算，不是账单。** 问数用 deepseek-v4-pro，深度研究用 qwen3.7-plus。深度研究未含搜索工具费，默认关闭，不进日均 150 次。

---

## 1. 开口三句

**问数：** 「一次 Chat-BI 大约 15 秒、整链 4k 到 10k token。全开大约 4 厘 6 一次，简历上日均 150 次，一天大约 7 毛，一个月大约 21 块。记忆自动评审另计，一天大约 12 条、1.5 万 token、5 厘，加进去还是 7 毛。」

**深度研究：** 「一次任务平均 9 分钟、输入 36 万、输出 1.5 万、大约 4 毛 4。P95 大约 13 分钟、输入 69 万、输出 2 万、6 毛 5。模型是 qwen3.7-plus，按千问 Plus 刊例、含缓存命中来算。」

**为什么默认关：** 「问数一次大约 4 厘 6、15 秒；深度研究一次平均 9 分钟、输入 36 万、输出 1.5 万、4 毛 4，大约贵 100 倍。每条问数都打研究，延迟和账单一起爆。」

## 3. 智能问数：15 秒怎么拆

全开一次（规则映射 + Embedding + 消歧 + S2SQL + 执行 + 解读）对齐标称 **15 秒**、token **入 9.5k / 出 0.73k**。三次模型调用大约 11 秒，规则、检索和 SQL 大约 4 秒。Token 只有三次 LLM 才有；前面的映射和后面的执行是 0。

秒数没有分段打点。消歧取已有区间 1–3 秒的中值，解读取已有上沿「通常 &lt;2 秒」。S2SQL 是三次调用里 prompt 最长的一次，剩下的墙钟主要给它。SQL 在约 1000 万行、10GB 上给 2.5 秒，不是大头。

| 环节 | 秒 | 输入 | 输出 | 单次费用 |
| --- | ---: | ---: | ---: | ---: |
| 规则映射（HanLP / 词典） | 0.5 | 0 | 0 | 0 |
| Embedding 召回 | 0.5 | 0 | 0 | 0 |
| Schema 消歧 | 2 | 2.0k | 80 | ≈¥0.00053 |
| S2SQL（5-shot） | 7 | 6.0k | 250 | ≈¥0.00165 |
| 校正与翻译 | 0.5 | 0 | 0 | 0 |
| SQL 执行 | 2.5 | 0 | 0 | 0 |
| 描述性解读 | 2 | 1.5k | 400 | ≈¥0.00244 |
| **合计** | **15** | **9.5k** | **0.73k** | **≈¥0.0046** |

单价是 deepseek-v4-pro 输入 ¥0.025 / 百万、输出 ¥6 / 百万。解读输出最长，这一步最贵。

P50 ~8 秒是少了两步的常见路径：STRICT / MODERATE 不跑 Embedding 和消歧，少约 2.5 秒，S2SQL 和 SQL 也更短。15 秒是全开、落在 P50–P75 的那一档。

### 一天的费用

简历日均 **150 次**。按上面的全开单次乘：

| | 一天 | 算法 |
| --- | ---: | --- |
| Token | 入约 **142 万** / 出约 **11 万** | 150 × 9.5k / 150 × 0.73k |
| 费用 | **≈¥0.70** | 150 × ¥0.0046 |
| 一个月 | **≈¥21** | ¥0.70 × 30，仍不含深度研究 |

这是全开上沿。常见路径跳过消歧，单次少 ¥0.00053，一天大约少 8 分，开口仍说 **一天大约 7 毛**。

### 记忆自动评审

不在用户那 15 秒里。`MemoryReviewTask` 每小时扫一轮，只审新落库的 PENDING：执行成功且是 LLM_S2SQL，同问句已有 ENABLED 的不再写。看的是 Question、Schema、SideInfo、SQL，不看结果表。

一天大约 **12 条**，不是 150 条。两个锚：库里 800+ 条 ENABLED，摊到在岗大约半年、一天新启用个位数；每周人工队列里的 NEGATIVE 是十几到三十条，大约一天 4 条。两边相加约 10–12 条，按 12 算。

| | 一条 | 一天 12 条 |
| --- | ---: | ---: |
| 输入 | ~1.2k | ~1.4 万 |
| 输出 | ~60 | ~720 |
| 费用 | ≈¥0.00039 | **≈¥0.005** |

输出仍是大头：60 个输出 token 的钱是 1.2k 输入的十倍以上。一天 5 厘，加进问数账单里看不出来。问数加评审，一天还是 **大约 7 毛**。

## 4. 深度研究：一次任务

样本是 2026-08-09 跑完的 3 题。耗时用 `step_logs` 首尾时间戳。Token 用该题全部 `usage_calculation` 的 Input、Output 分别相加（Main + 各 Sub）。输出含 reasoning。输入含缓存命中，不另计一份。模型是 **qwen3.7-plus**，百炼千问 Plus 的当前档。单价按中国内地、单次输入 ≤256K：输入 **¥2**、输出 **¥8**、缓存命中 **¥0.4**，每百万 token。费用含缓存，不含搜索工具费。

P95、P99 是这 3 个数的线性分位，都贴着最慢那题（13.3 分钟、输入 74.3 万、输出 2.1 万、¥0.68）。

| | 平均 | P95 | P99 |
| --- | ---: | ---: | ---: |
| 耗时 | **545 秒（9.1 分钟）** | 782 秒（13.0 分钟） | 796 秒（13.3 分钟） |
| 输入 | **35.9 万** | 68.9 万 | 73.3 万 |
| 输出 | **1.5 万** | 2.0 万 | 2.1 万 |
| 费用 | **¥0.44** | ¥0.65 | ¥0.67 |

一次任务里的时间，三题各自加总后再平均。Token 按会话归：工具不调模型。总结和 Main 推理写在同一张 Main 账单里，日志拆不出总结单独的输入、输出。

| 环节 | 平均耗时 | 输入 | 输出 |
| --- | ---: | ---: | ---: |
| Main 推理（规划、再委派） | 214 秒 | 会话合计 **2.6 万**（含总结） | **5.9k**（含总结） |
| Sub 推理 | 122 秒 | 会话合计 **33.3 万**（含各 Sub 收尾总结） | **9.0k** |
| 工具调用 | 137 秒 | 0 | 0 |
| 总结 | 48 秒 | 已含在 Main 的 2.6 万 | 已含在 Main 的 5.9k |
| 衔接 | 24 秒 | 0 | 0 |
| **合计** | **545 秒** | **35.9 万** | **1.5 万** |

单次模型调用是会话累计除以调用次数。Main 15 次（12 轮推理 + 3 次总结），Sub 62 次（55 轮推理 + 7 次收尾总结）。前缀在每一轮都重新计入输入。

| 一步 | 平均耗时 | 输入 | 输出 |
| --- | ---: | ---: | ---: |
| Main 一次调用 | 推理轮 54 秒；总结另 48 秒 | **5.2k** | **1.2k** |
| Sub 一次调用 | 推理轮 7 秒 | **1.6 万** | **440** |
| 工具一次 | 9 秒 | 0 | 0 |

最终报告是 Main 总结写入 `final_answer_content` 的正文，去掉日志前缀。三题都是英文。字数按字符计，含标点与空白。Token 用 Qwen3 词表数这段正文，不加 special token。这是报告本身的长度，不是上面的账单：账单输出平均 1.5 万，里面还有 reasoning 和每一轮的回复。

| | 平均 | P95 | P99 |
| --- | ---: | ---: | ---: |
| 字数 | **2871** | 3444 | 3474 |
| Token | **843** | 931 | 942 |

最慢那题（Nature，13.3 分钟）的报告是 3108 字、800 token，不是三题里最长的。最长的是 Mercedes，3481 字、945 token。

## 5. 追问时只补这些

**「15 秒里哪一段最慢？」** 全开拆解见 §3。S2SQL 大约 7 秒，是最长的一段；消歧和解读各约 2 秒。P50 大约 8 秒，那是没跑 Embedding 和消歧的常见路径。

**「为什么深度研究这么贵？」** 见 §4。一次任务平均输入 35.9 万、输出 1.5 万、¥0.44。输入里约 33.3 万在 Sub。贵在多轮把前缀反复读进输入。最终报告本身平均只有 2871 字、843 token。

**「一天的研究账单呢？」** 不报。深度研究不是日均 150 次都打，默认关。没有「每天几条研究」的埋点，就不乘出日费用。

**「token 怎么统计的？」** 问数：每次 LLM 回执打 `llmTokenCount`，同一次查询按 `traceId` 加总，Kibana 按模型和天看。深度研究：一个 attempt 里每段 `usage_calculation` 的 Input、Output 分开加总，Main 和 Sub 都算。Cached 留在 Input 里，费用再按缓存单价拆。
