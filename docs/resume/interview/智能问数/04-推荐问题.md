# 推荐问题（内置 15% + 相似 11%）

## 诚实边界总表

| 说法 | 可讲 | 不可讲 |
|------|------|--------|
| **相似** | Parse 后异步；只读记忆库 question | 「边输入边联想就是本模块」 |
| **内置** | Agent.examples 列表 | 「等于 preset_query_collection」 |
| **同库** | 与 03 同一 `memory_{agentId}`；推荐不写库 | 「推荐另有一套写入链路」 |
| **source 15%/11%** | 产品贡献率口径 | 「Java 主链路已有 source 枚举」（全栈未检索到） |
| **竞态** | queryId 回写；用户已进下一问则挂在旧题旁 | 「已上线 version 协议」 |

## Part A · 需求与效果

### A1 背景与动机

推荐要拆场景——不是全站统一痛点，更不是「用户不会提问」。

**主场景：行为实验开展期，实验助理反复查 + 连续追问**

谁在问：兼职大学生、实习生，在实验实施的约 4 周内高频查运维题——没发报酬有哪些人、校准失败要不要补招、场次男女比例、实验预算花了/剩下/人均多少。骨架固定，变的是实验名和场次。查完报酬名单后，下一步常问预算、校准失败人数或样本结构——这是一张固定运维清单上的连续追问，不是随机发散。

**次场景：绿色金融等金融经济研究，引导开口**

实证研究一次一问、换假设就换结构，不像实验运维那样近重复扎堆。痛点是「这套库自然语言怎么起头才问得出面板」——内置引导题是开口模板，点下去走完整问数链路。

一句话：相似吃「查完 A 还要问 B」；内置吃「不知道怎么开口」。两条通道互补，权重不同。

### A2 目标与非目标

**目标**：

- 降低开口成本：内置引导题让绿色金融用户点一下就走完整链路
- 结果旁下一跳：相似推荐把历史成功问法摊在结果区，助理连着点下去

**非目标**：

- 输入联想：边打边出的联想是另一套 search/recommend，不是本模块
- 另建推荐向量库：与 [03 记忆复用](./03-查询记忆复用.md) 共用同一 `memory_{agentId}`
- 替代记忆复用：相似只取 question 展示，不教 Parser 写法

### A3 已实现效果

双通道统一用**查询贡献率**度量——分母都是总查询次数，分子分别是内置 / 相似来源的查询数（详见 A4 口径）。

| 指标 | 数值 | 日均 150 次时约 |
|------|------|----------------|
| 内置贡献率 | **15%** | ~23 次 |
| 相似贡献率 | **11%** | ~17 次 |
| 合计 | **26%** | ~40 次 |

行为实验侧——相似推荐代表性样例：

| 问法 | 推荐来源 | 连续追问链 |
|------|---------|-----------|
| 「xxx 实验未发报酬人员有哪些」 | 内置 FAQ | → 预算花了/剩/人均 |
| 「注意力校准失败的被试有多少」 | 相似近邻 | → 要不要补招 |
| 「xxx 实验预算花了多少 / 还剩多少 / 人均多少」 | 相似近邻 | 查完报酬常被推 |

绿色金融侧——内置引导题代表性样例：

| 引导题 | 示范什么 |
|--------|---------|
| 绿色金融改革试验区地级市 2010–2020 碳排放、GDP、第二产业占比面板 | 政策试点 × 面板口径 |
| A 股公司按 ESG 评级分组平均 ROA / Tobin's Q，区分国企与非国企 | ESG × 财务 × 所有制异质 |

### A4 指标口径

每次真正提交问数打一条 `query_submit`，带归因字段 `source`：

| source 枚举 | 含义 |
|-------------|------|
| `manual` | 手打提交 |
| `preset` | 点内置推荐触发 |
| `similar` | 点相似推荐触发 |

贡献率公式：`count(source=X) / count(全部 query_submit)`。

**为什么不用 impression CTR**：内部 B 端工具，关心的是「有多少查询真的从推荐进来」，不是资讯流式曝光点击。只看了推荐没提交，不进分子，也不单独当主 KPI。

| 指标 | 公式 | 简历值 |
|------|------|--------|
| 内置贡献率 | `count(source=preset) / count(全部)` | **15%** |
| 相似贡献率 | `count(source=similar) / count(全部)` | **11%** |

**诚实标注**：`source` 枚举在当前 OSS Java 主链路与前端 chat-sdk 中均**未检索到**（`SimilarQueryRecallResp` 只有 `queryId` + `queryText`；前端 `SimilarQuestionType` 只有 `queryId` + `parseId` + `queryText`）。15% / 11% 为 `[产品/ELK 口径]`，需与 ELK 自定义埋点字段对齐后方可代码化验证。

### A5 与 03 边界

一个库，两种读法——教模型 vs 给人点。

| | [03 记忆复用](./03-查询记忆复用.md) | 本文推荐问题 |
|--|--|--|
| **集合** | `memory_{agentId}` | 同一个 |
| **时机** | Parser **前**同步 | Parse **后**异步 |
| **消费** | 四元组 → `#Exemplars` 教 Parser | 仅 `question` 展示给人点 |
| **写入** | Review ENABLED 后 `storeExemplar` | 不写库，只读 |

详细工程差异见 03 文；本文不展开 Review / `#Exemplars` 细节。

### A6 实现难点与过程困难

推荐不是「挂个列表就完事」，过程踩过的坑收在下面，每条对应后文 B 节展开。

#### 1. 场景易说成全站痛点

**难在哪：** 推荐很容易被讲成「用户不会提问」这种全站泛痛点，但实际只覆盖两个窄场景，一旦说大就会被追问到没有数据支撑的地方。

**当时怎么扛：** 叙事只拆两块——行为实验助理反复查（相似通道主战场）和绿色金融引导开口（内置通道），不往全站延伸（→ A1）。

**留下什么：** 讲场景时先把范围锁死再谈数字，否则贡献率口径经不起追问。→ A1；B1/B2

#### 2. 贡献率 ≠ 少打字证明

**难在哪：** 15%/11% 只说明「从推荐入口进来的查询占比」，不代表用户真的少打了字或更快得到答案。

**当时怎么扛：** 口径上只报贡献率（→ A4），不主动宣称「减少输入量」。更深一层要 source=similar|preset 子集看执行成功率，以及同骨架手打是否下降。

**留下什么：** 被追问「怎么证明有用」时，先承认观测指标非因果，再说可做的深化方向。→ A4；B5

#### 3. async 空态 / 超时

**难在哪：** 相似推荐是 Parse 后异步召回，OSS 没有专门的 timeout UI 协议——异步慢则列表暂空，用户看到的就是「推荐区什么都没有」。

**当时怎么扛：** 前端 `useEffect` 在 expanded 时再拉一次（等异步写完），用户进下一问则推荐挂在旧题旁。

**留下什么：** 空态不是 bug，是异步时序的固有表现，但需要在不加 OSS 协议的前提下做好体验兜底。→ B2/B4

#### 4. examples vs plugin preset 易混

**难在哪：** `Agent.examples`（前端进门展示的内置引导题）和 `EmbeddingConfig.presetCollection`（默认 `preset_query_collection`，给 Plugin 识别用，`PluginManager` 消费）名字相近、职责不同，面试常被追问混淆。

**当时怎么扛：** 在诚实边界表里明确区分两者的消费者和生命周期（→ 文首表），面试时主动说清。

**留下什么：** 两个集合的边界是推荐模块最容易答错的知识点，必须背熟。→ B1；诚实边界表

#### 5. 推错近邻放大风险

**难在哪：** 相似推荐只推 ENABLED 近邻（依赖 03 治理），但 ENABLED 仍可能语义错——比如「去年」按滚动 365 天召回，季节性题目会被教坏。

**当时怎么扛：** 错范文先治 03 记忆库（Review 流程卡 ENABLED），不从推荐侧做过滤。

**留下什么：** 推荐的准确率上限被上游记忆库质量锁死，推荐模块自己弥补不了。→ B4；链 03 B4.1

#### 6. 缺严肃 A/B

**难在哪：** 贡献率是观测指标，不是因果推断——没有 randomized exposure，也没按 Agent / 实验周切片做常态化看板。

**当时怎么扛：** 口径上只报产品贡献率，不宣称 A/B 效果。

**留下什么：** 如果要做严肃因果评估，需要按 Agent 分组、控制曝光、做差异检验。→ B5 P0/P2

## Part B · 工程 Spec

### B0 先看清两条路

> 面试场景：「推荐模块整体怎么串的？」——先画双通道，再点类。

#### B0.1 主线箭头图

```
        ┌─ B1 通道一：进门内置 ─┐
用户 ───┤                       ├──► B3 汇合：点推荐 = 新开一轮完整问数
        └─ B2 通道二：查完相似 ─┘
              ∥  ← B1 ∥ B2 并行
                 │
                 ▼
        B4 晚了 / 空了 / 推歪了
                 │
                 ▼
        B5 下一刀往哪砍
```

| 关系 | 含义 |
|------|------|
| **B1 ∥ B2** | 并行双通道，不是先后工序 |
| **B3** | 两通道的**共同出口**（点击后果） |
| **时间线** | 会话中常先遇 B1、查完再遇 B2；但用户纯手打（不点 B1）也会触发 B2——B2 不依赖 B1 被点过 |

#### B0.2 类职责表

| 职责 | 类·方法/字段 |
|------|-------------|
| 相似异步主类 | `QueryRecommendProcessor.process` |
| 召回方法 | `QueryRecommendProcessor.getSimilarQueries`（调 `recallExemplars`，topK=5 硬编码） |
| 持久化字段 | `ChatQueryDO.similarQueries`（String JSON） |
| 内置配置 | `Agent.examples`（List\<String\>）/ `AgentDO.examples`（String JSON） |

#### B0.4 一行 03 对照

> 与 03 同库只读、不进 `#Exemplars`、链 [03-查询记忆复用](./03-查询记忆复用.md) A5——**不**设同库专章。

### B1 通道一：进门内置

> 场景：用户打开问数页，还没开口——内置题告诉他「可以这样问」。
> 绿色金融第一次不知怎么起头、行为助理进门前要看的 FAQ 清单，都走这条。

#### B1.1 存储：`Agent.examples`

- Domain 层：`Agent.examples` 是 `List<String>`
- DB 层：`AgentDO.examples` 是 **String JSON**
- DO ↔ Domain 转换在 `AgentServiceImpl`：`JsonUtil.toList` / `JsonUtil.toString`

#### B1.2 前端展示 + 点下去 = 新 query

- chat-sdk 进门拉 `Agent.examples`，结果区渲染可点列表
- 用户点某条 example → 前端把文字当 `queryText` 提交，走完整 `parseAndExecute`（B3 展开）

#### B1.3 冷启动种子自动执行

`AgentServiceImpl.doExecuteAgentExamples` 是 **03 冷启动种子的自动入口之一**（跑 examples 成功 + `agent.enableMemoryReview()` 开 → 入记忆库当种子），**本文不展开 Review 细节，链 [03 B5](./03-查询记忆复用.md)**。

前置条件：`agent.containsDatasetTool() && enableMemoryReview() && examples 非空`

```java
private synchronized void doExecuteAgentExamples(Agent agent) {
    if (!agent.containsDatasetTool() || !agent.enableMemoryReview()
            || CollectionUtils.isEmpty(agent.getExamples())) {
        return;
    }
    // …调 chatQueryService.parseAndExecute，成功则按 03 B2 走 PENDING → Review
}
```

#### B1.4 数据形状

```json
{
  "agentId": 10,
  "agentName": "绿色金融",
  "examples": [
    "绿色金融改革试验区地级市 2010–2020 年碳排放、GDP、第二产业占比面板",
    "A 股公司按 ESG 评级分组的平均 ROA / Tobin's Q，区分国企与非国企"
  ]
}
```

#### B1.5 勿混 `preset_query_collection`

`EmbeddingConfig.presetCollection`（字段名，默认 `preset_query_collection`）给 **Plugin** embedding 识别用（`PluginManager.recognize` 消费），不是结果旁「点一下再查」的内置 FAQ 列表——**两套不互通**。

#### 易踩坑

- `Agent.examples`（前端展示 + 点下去当 query）vs `EmbeddingConfig.presetCollection`（默认 `preset_query_collection`，给 **Plugin** 识别用）——**两套不互通**
- `AgentDO.examples` 是 String JSON，`Agent.examples` 是 `List<String>`——DO ↔ Domain 序列化在 `AgentServiceImpl`（`JsonUtil.toList` / `JsonUtil.toString`）
- `doExecuteAgentExamples` 是 `private synchronized`，通过 `executeAgentExamplesAsync` 在 **`chatExecutor` 线程池**触发（与 B2 `QueryRecommendProcessor` 的 ForkJoinPool.commonPool() **不是同一个池**——B4 详讲）
