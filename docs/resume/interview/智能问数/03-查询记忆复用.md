# 查询记忆复用（72% → 87%，800+ 条）

## 诚实边界总表

| 说法 | 可讲 | 不可讲 |
|------|------|--------|
| **实现归属** | 开源 SuperSonic 链路；业务侧开 Review、冷启动、人审、评测 | 「我从零自研记忆向量框架」 |
| **审核形态** | `POSITIVE` / `NEGATIVE`；人审；反馈 score>=5/<=1 | 「1-5 分、>=4 自动入库」 |
| **召回条数** | 向量召回 **10** -> 注入约 **5** | 「Top-3 few-shot」作主口径 |
| **评测集** | 离线 **200**、无 HITL；T1->T2 +15pp | 「线上 300」作 87% 主口径 |
| **表字段** | 无表内 embedding、无复用次数 | 「表里有 hit count」 |
| **执行成功** | 只 PENDING；ENABLED 要过审 | 「不报错就进 few-shot」 |
| **NEGATIVE** | 记 llm_review；status 常仍 PENDING | 「NEGATIVE 自动 DISABLED」 |
| **推荐 / version** | 一行链 04；async 按 queryId | 编造 OSS「版本号协议」 |

## Part A · 需求与效果

### A1 背景与动机

SchemaMapper 把字段映射做到 81% 后，端到端卡在 72%——字段常选对，**Parser 仍因 Few-shot 结构不对齐翻车**。

核心痛点：Text2SQL 准确率高度依赖范文的**结构相似度**，而系统只有一套 JSON 写死的静态范文（演示域「超音数」），对金融题不但帮不上忙还会教坏——比如把「去年」教成滚动 365 天，和金融场景「自然年」的语义完全错位。

业界已反复验证这一点：DIN-SQL（NeurIPS 2023）表明合适的 in-context 示例可带来约 +10pp 提升量级；DAIL-SQL（Gao et al., arXiv:2308.15363）显示精选示例显著优于随机选取。静态写死 demonstration 在范文与当前题差距大时会出现 retrieval bias，LLM 被不相关示例带偏。

替代方案对比：

| 方案 | 做法 | 不足 |
|------|------|------|
| 堆静态 Few-shot | 每种骨架手写进 JSON | 滞后线上；堆数量不等于选得准；token/维护双爆 |
| 全量塞 prompt | 几十条全进 `#Exemplars` | 超上下文；噪声大 |
| 微调专用模型 | 用成功 SQL 微调 | 成本高、迭代慢 |
| **动态检索同构范文**（我们选的） | 成功过审 -> 向量库 -> 按 query 召回注入 | 对齐 example selection；范文随业务增长 |

一句话：Parser 不是缺「几条 SQL」，缺的是「跟当前题同构的成功写法」。

### A2 目标与非目标

**目标**：成功 SQL 过审后入库，Parser 按相似度动态召回同构范文注入 `#Exemplars`，提升端到端准确率。

**非目标**：

- 自研向量框架——基于开源 SuperSonic 链路，业务侧负责开 Review、冷启动、人审运营与评测
- 替代 SchemaMapper——记忆复用作用于 Parser 阶段，与字段映射是上下游关系
- 为相似推荐单独建模——两者共用同一向量库，推荐只取 question 展示（详见 [04](./04-推荐问题.md)）

### A3 已实现效果

端到端准确率从 **72% 提升到 87%**（同一批 200 条离线评测集，无 HITL）；其中 T1->T2 的 **+15pp** 几乎全部归因于记忆库（SchemaMapper 在 T1 已优化完毕，映射 EM 保持在 81%）。

记忆库累计 **800+ 条 ENABLED**，其中冷启动种子 **200 条**（4 个 Agent 按主题域分摊），4-7 月线上沉淀约 600 条。

在 Schema 已正确的子集上，Parser 条件准确率约 **75% -> 90%**。

### A4 评测口径

评测基于自维护离线集，**同一批 200 条**贯穿全部阶段，中间无人工干预（无 HITL）。

| 阶段 | 端到端准确率 | Schema EM | Parser 条件准确率（Schema 正确子集） | 说明 |
|------|------------|-----------|----------------------------------|------|
| T0（加入时） | 45% | 58% | — | 端到端测评集已就绪 |
| T1（Schema + LLM 消歧） | 72% (+27pp) | 81% (+23pp) | ~75% | 记忆库未上线 |
| T2（记忆库上线） | 87% (+15pp) | 81% | ~90% (+15pp) | +15pp 全归因记忆库 |

Parser 条件准确率是端到端集上的条件切片（Schema EM 正确的前提下看最终答案是否对），不是另建一套 S2SQL Exact Match 评测集。

判定方式：执行结果是否满足 gold_answer 的口径约束 + 五维度语义评分（字段、实体、时间、聚合、量级）。

### A5 与 02/04 边界

| 模块 | 链路位置 | 消费什么 | 面试一句 |
|------|---------|---------|---------|
| [02 SchemaMapper](./02-SchemaMapper.md) | 映射阶段 | 字段 -> 本轮 `{{schema}}` | 选对字段 |
