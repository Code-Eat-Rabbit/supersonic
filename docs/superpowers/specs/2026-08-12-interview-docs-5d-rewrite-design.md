## 一、背景与动机

用户基于 SuperSonic 项目包装简历参加面试，现有面试文档采用"诚实边界总表 + Part A/B/C"结构组织。根据实际面试经验，面试官常从 5 个维度发起询问：

1. 背景介绍（为什么做 / 怎么发现问题的）
2. 方案选型（考虑了哪些方案 / 如何权衡 / 和之前代码的关系）
3. 行动计划（怎么一步步写出来的）
4. 迭代优化（遇到什么问题，怎么克服）
5. 成果展示（怎么衡量 / 效果如何）

现有文档结构在这 5 个维度的覆盖上不均衡：背景和成果有，方案选型零散，行动计划几乎缺失，迭代优化只讲踩坑不讲克服过程。需要按 5 维度重组，让叙事顺序与面试官提问维度对齐。

## 三、02/03/04 统一新骨架

每篇专题文档按以下 5 个二级标题组织，彻底替换现有的"诚实边界 + Part A/B/C"结构：

```markdown
# {技术专题}（{起始准确率} → {目标准确率}）

> 系列：智能问数
> 简历基线：[../../my_resume.md](../../my_resume.md)
> 总览：[01-总览与业务背景.md](./01-总览与业务背景.md)
> 上一篇：[xx-xxx](./xx-xxx.md) · 下一篇：[xx-xxx](./xx-xxx.md)

---

## 1. 背景：为什么做，怎么发现的问题

- 痛点（用户故事 + 量化）
- 发现路径（ELK 日志 / 用户反馈 / 数据分析）
- 量化瓶颈（准确率卡在哪）

## 2. 方案选型：考虑了哪些方案，如何权衡

- 候选方案对比表
- 选型理由
- 和现有代码的关系（在哪个环节切入，改了哪些类）

## 3. 行动计划：怎么一步步写出来的

按真实 git 时序组织（包装成"我"的工作），关键类名/方法带在叙事里：
- 第一步：[对应具体动作]
- 第二步：...
- 数据结构/调用链作为叙事支撑

## 4. 迭代优化：遇到什么问题，怎么克服

- 踩坑 1：xxx → 解决
- 踩坑 2：xxx → 解决
- （来源：现有 A6 实现难点 + git 考古的 bug 修复）

## 5. 成果展示：怎么衡量，效果如何

- 评测口径
- 指标表格
- 业务影响 / 代表性样例
```

**保留元素**：文档头系列导航、技术专题标题里的起止准确率。

**删除元素**：诚实边界总表、Part A/B/C 三段式标签、题纲索引、回看清单。

## 八、诚实性边界（包装策略的底线）

虽然包装成"我"的工作，但以下底线必须守住：

1. **不编造能力**——模块 2 不讲"从零自研记忆向量框架"；向量库（pgvector）作为技术选型在方案选型里讲。

4. **数字与 git 可查证**——commit hash、日期、代码量都要与 git 历史一致；"200 条种子"用"约 200 条"或"百量级"表述。
