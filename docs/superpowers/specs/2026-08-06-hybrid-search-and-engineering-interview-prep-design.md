同时：

- `03` 已按「调用链精读 + 题索引」模式拆出 E 节；F/G 应沿用同一迁移模式。
- `03` §8–§9 已写预算与并发，与 G22/G23 重叠；若不收口，两处长文会口径漂移。
- 业务知识库主内容是**访谈材料 + 清洗后的研报**，`02` F20 里偏泛化的「实验材料 / 制度文档」清单需按业务口径收紧。

### 1.2 目标

1. 新建 `深度研究/04-Hybrid-Search-MCP.md`：先工具 harness，再 Hybrid Search，再业务库与案例；承接 F17–F20。
2. 新建 `深度研究/05-工程化能力.md`：追踪回放、预算熔断、两类并发、断点续跑；承接 G21–G24，并成为预算/并发的权威详解。
3. `02` 的 F/G 整段迁出为题号索引（同 E→`03`）；对照表锚点改指 `04`/`05`。
4. `03` §8–§9 收成短指针，链到 `05`；编排主线（§1–§7）不动。
5. 口径与 L0 事实库、简历诚实边界一致。

### 1.3 非目标

- 不改 `miro-flow-solution` / SuperSonic 功能代码。
- 不重写 `01-集成设计.md` 全文（默认不改；仅当已有「见 02 F/G」指针时补交叉引用）。
- 不虚构知识库规模、向量条数、断点续跑「节省 X 小时」、生产事故损失。
- 不把 `vector_backend` 说成已上线生产向量库。
- 不把评测多题并行说成单题内子 Agent 已并行。

## 5. `04` 内容规格

### 5.1 与 `03` 的衔接（写入 §1）

- `03` 主循环：有 tool call 时，**普通 MCP** 走 `ToolManager.execute`；`agent-*` 走 `run_sub_agent`。
- 本章从「工具怎么进系统、怎么被找到、怎么跑、失败怎么办」接到「Hybrid Search 这一把工具的特点」。
- `agent-*` 伪工具不在本章展开（归 `03`）。

### 5.2 工具 harness（写入 §2）

标本锚点：

- 注册：`config/tool/tool-*.yaml`（含 `tool-hybrid-search.yaml`）；Sub Agent `tool_config` 挂载
- 发现/调用：`src/tool/manager.py` 的 `execute_tool_call`
- 降级：超时、空内容、Server 名纠错（唯一拥有该工具的 server 时自动纠正）、备用读取（如 MarkItDown）

必须钉死：

- **98%** = 单次 MCP 工具调用返回可解析、非空、可被 Agent 继续消费的有效结果；≠ 任务成功率 / 答案准确率 / GAIA 通过率
- 降级顺序可背：同工具限次重试或纠正 → 备选工具/来源 → 基于已有证据部分完成；仅最终报告不可用或总超时才回退描述性解读（产品层，链到 D10–D11）

### 5.3 Hybrid Search（写入 §3）

标本锚点：`router.py` / `ingest.py` / `local_index.py` / `vector_backend.py` / `web_retriever.py` / `fusion.py` / `schemas.py` / `hybrid_search_mcp_server.py`

必须钉死：

- 强制 `mode` 优先；无本地索引 → web + reason；hints：仅 local → local，仅 web → web，双命中或都未命中 → hybrid（默认）
- 默认权重 0.6/0.4 为标本基线，归一化后加权排序、按 URL 或「来源+chunk_id」去重、Top K
- `VectorBackend` 当前回退本地索引，不包装成生产向量库

#### 5.3.1 证据链与引用（§3 末必须有）

**工具层（可核对）：** `SearchHit` 含 `source` / `title` / `url` / `snippet` / `score` / `chunk_id` / `metadata`；MCP 返回另含 `route` / `reason` / `mix` / 两路召回数。

**报告层（诚实口径）：**

- Sub/Main Prompt：优先摘录原文并给 URL；来源不确定要标明；关键事实写清出处与是否交叉验证
- 业务 ResearchDirective（见 `01`）：金融归因标证据强度；学术禁编造引用
- **无**代码级「强制 JSON 引用列表 / 脚注 schema 校验」；引用质量靠结构化 hit + Prompt，不是编译期保证
- 冲突时保留出处与不确定性，不因分高覆盖原始访谈/研报；一路失败仍交已验证部分并声明缺口

面试一句话：Hybrid 先产出可追溯 hit 列表；Agent 按出处摘录并标强度/缺口；不假装引用未召回材料。

### 5.4 业务知识库与案例（写入 §4）

**存什么（主口径）：**

- 经授权的**访谈材料**
- **清洗后的研报**（可追溯来源、版本/更新时间等元数据，以业务可讲为准）
- 每个分块保留来源、标题、chunk id，便于回答时回溯

**不写进主库存量（无额外依据时）：** 泛化「实验方案 / 制度文档大全」等；若提及，标明非本库主内容。

**维护：** 上传 → 文本抽取（文本直读 / MarkItDown）→ chunk → 索引写入；修订 upsert/重建。标本可核对抽取与索引；审批流/权限治理讲原则，不宣称标本已完整落地。

**F19：** 保留金融归因 + 行为科学两骨架；强调时间相邻≠因果、不编造论文标题/页码；用 §3 机制讲故事。

### 5.5 题索引（写入 §5）

从 `02` 迁入 F17–F20：保留「第一句 / 要点 / 易踩坑」，并加「详见 §x」链接；回看清单列文件路径。

## 6. `05` 内容规格

### 6.1 与前两章的关系（写入 §1）

| 文档 | 管什么 |
|------|--------|
| `03` | 编排决策与会话隔离（Main–Sub） |
| `04` | 工具注册/调用/降级与 Hybrid 检索 |
| `05` | 可观测、预算熔断、评测并发、断点续跑 |

### 6.2 追踪回放（写入 §2 / G21）

标本：`task_tracer.py`（`StepRecord` / `TaskTracer`）、`orchestrator.py` 阶段性 `save`、`pipeline.py` `finally` 终态。

必须钉死：按 `task_id` → step 时间线 → message history / metadata 回放；异常前链路通常可保留；不虚构具体生产事故与损失；不把仅定义未持续更新的字段说成已完整驱动回放。

### 6.3 预算与并发（写入 §3 / G22–G23）

从 `03` §8–§9 **迁入权威详解**：

- `max_turns` vs `max_tool_calls_per_turn`（标本 Main 20/10、Sub worker 50/10 仅示例）
- 触顶后尝试 final summary，≠ 立刻丢弃证据
- 评测多题：`Semaphore` + `gather(return_exceptions=True)`；单题内 tool call 顺序 `for`
- 简历「并发」可背口径：架构可并行无依赖子任务；标本单题内顺序；业务并行需另加上限/超时/隔离

`03` 侧仅留编排语义一句 + 指针。

### 6.4 断点续跑（写入 §4 / G24）

标本：`common_benchmark.py` 的 `scan_latest_attempt` / `run_single_task`。

必须钉死：文件存在 ≠ 完成；状态提升路径 `RUN_FAILED` → 有 boxed → `RUN_COMPLETED` → 有 judge → `RESULT_JUDGED`；pass@k 提前停；省时只讲机制，不报未测小时数/百分比。

### 6.5 题索引（写入 §5）

迁入 G21–G24；附录写明 `03` §8–§9 已改为详见本文 §3。

## 7. 诚实边界总表（写入两篇 §1）

### 7.1 `04` 专用

| 说法 | 可讲 | 不可讲 |
|------|------|--------|
| 98% | 单次工具调用有效结果率 | 任务成功率 / 答案准确率 / GAIA 通过率 |
| 路由 | 关键词 hints + 强制 mode + 无索引降级 | 「已是语义理解路由 / 已上线学习型路由」（无依据时） |
| 权重 0.6/0.4 | 标本默认基线 | 业务最优参数 |
| 向量 | 接口存在、当前回退本地索引 | 生产向量库已完整落地 |
| 知识库 | 访谈材料 + 清洗研报；可追溯字段 | 虚构库规模 / 向量条数 |
| 引用 | hit 字段 + Prompt/Directive 约束 | 代码级引用 schema 强校验已落地 |

### 7.2 `05` 专用

| 说法 | 可讲 | 不可讲 |
|------|------|--------|
| 并发 | 多题并行隔离；单题内顺序；架构可演进并行 | 标本已 `gather` 子 Agent；`10` = 同时跑 10 个 |
| 熔断参数 | 标本配置示例；触顶仍可 summary | 线上已验证最优；熔断绝不误伤 |
| 续跑省时 | 跳过已完成 attempt 的机制 | 无数据时报「节省 X 小时」 |
| 超时 660s | `n=3` 临时建议 | 正式 P95 / SLA |
